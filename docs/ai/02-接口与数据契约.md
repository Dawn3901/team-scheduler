# AI 约束 02 · 接口与数据契约

版本：v1.0  
日期：2026-10-27  
适用：后端/前端/三端 AI 编码助手  
目的：**契约是法律。** 防止 AI 为了“跑通”而改名、加字段、改状态码、绕过序列化、手改表。

---

## 1. 冻结窗口

| 契约 | 冻结时间 | 冻结内容 | 变更方式 |
|---|---|---|---|
| API | W1 周五 | 路径、方法、字段名、错误码、分页、时间格式、WS 类型 | CR + 前后端确认 + 文档 + 契约测试 |
| DB | W2 周五 | 表、列、类型、枚举、索引、软删除、唯一约束 | CR + ADR + Alembic 迁移 + 备份 |
| WS | W3 周五 | 消息类型、payload 最小字段、鉴权方式 | CR + 前后端 + 文档 |
| 演示脚本 | W5 周五 | 演示路径 | 只修 bug，不加功能 |

冻结后不是“绝对不能改”，而是**不能静默改**。任何变更必须留下记录。

## 2. API 约定（不可协商）

| 项 | 规定 |
|---|---|
| Base | `/api/v1` |
| 认证 | `Authorization: Bearer <jwt>` |
| 内容 | `application/json`；字段 `snake_case` |
| 时间 | ISO 8601 UTC，`2026-11-04T06:30:00Z` |
| 分页 | `limit`（默认 20，最大 100）、`offset` |
| 列表 | `{ "items": [], "total": 0 }` |
| 错误 | `{ "code": "...", "message": "...", "details": {} }` |
| 事件查询 | 必须带 `from`/`to`，跨度 ≤ 92 天 |
| 忙闲查询 | 必须带 `from`/`to`，跨度 ≤ 31 天 |
| 删除 | 常规资源软删除；`DELETE` 返回 204 |
| 空响应 | 204 不带 body |

**禁止**：

- 把 `snake_case` 改成 `camelCase`（前端在 API Client 层做映射，不改后端）。
- 把时间改成毫秒时间戳/本地时间字符串。
- 列表直接返回数组（必须是 `{items,total}`）。
- 用 200 + `{success:false}` 代替 4xx。
- 用 403 代替 404 来“更明确”（会泄露资源存在）。
- 在响应里加未文档化的字段（前端不应依赖）。

## 4. 错误码（不得改名）

| HTTP | code | 场景 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 参数格式错误 |
| 401 | `UNAUTHORIZED` | 未登录/token 无效 |
| 401 | `INVALID_CREDENTIALS` | 用户名或密码错误 |
| 403 | `FORBIDDEN` | 角色不足 |
| 404 | `NOT_FOUND` | 资源不存在或不可见 |
| 405 | `METHOD_NOT_ALLOWED` | 方法不允许 |
| 409 | `USERNAME_TAKEN` | 用户名重复 |
| 409 | `INVITE_CODE_INVALID` | 邀请码错误/失效 |
| 409 | `TIME_CONFLICT` | 活动时间冲突 |
| 409 | `EVENT_CANCELLED` | 活动已取消 |
| 409 | `EVENT_ENDED` | 活动已结束，不能再邀请/RSVP |
| 422 | `INVALID_TIME_RANGE` | 结束不晚于开始 |
| 422 | `EVENT_ALREADY_STARTED` | 活动已开始，不能再改时间/地点 |
| 422 | `INVALID_PARTICIPANT` | 参与者不是成员 |
| 422 | `INVALID_ASSIGNEE` | 负责人不是成员 |
| 422 | `ORGANIZER_CANNOT_DECLINE` | 组织者不能拒绝 |
| 429 | `RATE_LIMITED` | 登录限流 |
| 500 | `INTERNAL_ERROR` | 未捕获异常 |

**禁止**：

- 改 code 字符串、大小写、拼写。
- 同一个场景在不同端点返回不同 code。
- 把冲突从 409 改成 200 + `conflicts`。
- 把权限不足从 403 改成 401。

## 5. 数据库契约

### 5.1 表

只允许 7 张核心表：

```text
users
teams
team_members
events
event_participants
tasks
notifications
```

新增表 = 数据模型变更 = CR + ADR + 迁移。

### 5.2 列与类型

- 主键：`INTEGER PRIMARY KEY AUTOINCREMENT`。
- 时间：`DATETIME`，应用层 UTC aware。
- 布尔：`INTEGER 0/1`（SQLite）。
- 枚举：`TEXT + CHECK`。
- 外键：必须声明 `REFERENCES`；SQLite 开 `PRAGMA foreign_keys=ON`。
- 软删除：`deleted_at DATETIME NULL`。
- 所有列表/详情默认过滤 `deleted_at IS NULL`。

### 5.3 关键约束

```text
users.username UNIQUE
users.email UNIQUE (nullable)
teams.invite_code UNIQUE
team_members UNIQUE(team_id, user_id)
event_participants UNIQUE(event_id, user_id)
events CHECK(start_at < end_at)
notifications.dedupe_key UNIQUE (nullable)
```

### 5.4 索引

```text
team_members(user_id, status)
events(team_id, start_at)
events(team_id, end_at)
event_participants(user_id)
tasks(team_id, due_at)
tasks(team_id, assignee_id, status)
notifications(user_id, read_at, created_at)
```

新增查询前先想索引；不要用 `LIKE '%x%'` 做核心查询。

### 5.5 迁移规则

1. 只通过 Alembic；禁止手写 `ALTER TABLE` 到数据库。
2. 一个 PR 一个迁移；命名 `YYYYMMDD_short_desc`。
3. 迁移必须能从空库跑到 head，也能从上一版升级。
4. 破坏性变更（删列/改类型）分两步：加新列 → 回填 → 删旧列。
5. 合并前备份 DB 跑一遍；CI 跑 `alembic upgrade head`。
6. 不改历史迁移文件；用新迁移修正。
7. 迁移失败必须回滚并报告，不要“删库重来”。

## 6. 多租户与权限契约

### 6.1 必须

```python
# 所有团队路由
member = Depends(require_member)  # 非成员 -> 404

# 所有按 id 取资源
event = db.get(Event, event_id)
if not event or event.team_id != team_id or event.deleted_at:
    raise NotFound()
```

- 列表查询必须带 `team_id` 过滤。
- 资源级权限：`can_edit_event` / `can_edit_task` / `can_view_event`。
- 跨团队测试：每个团队资源至少 1 条。

### 6.2 禁止

```python
# 错：只按 id 查
event = db.get(Event, event_id)

# 错：信任客户端传的 team_id
if body.team_id == event.team_id: ...

# 错：前端隐藏按钮就认为安全
if user.role != "admin": return  # 路由里漏了 owner
```

### 6.3 404 vs 403

| 场景 | 返回 |
|---|---|
| 非团队成员访问团队资源 | 404（不暴露团队存在） |
| 成员角色不足（Member 编辑他人活动） | 403 |
| 私密活动非参与者 | 404（不暴露活动存在） |
| 通知不属于当前用户 | 404 |

---

### 6.4 成员移除与并发

- 移除成员不是只改 `team_members.status`；必须按 `docs/03` §6.6 的多表事务处理任务、私密活动、参与者行、未读通知。
- Owner 不能被移除；Owner 退出必须先删除团队（转让 P1）。
- 并发编辑采用**最后写入生效**；不改契约、不加版本列；响应带 `updated_at` 供前端提示。
- 唯一约束冲突（重复加入/邀请/通知）转幂等或 409，不允许 500。

## 7. 私密脱敏契约

### 7.1 活动列表/详情

- `visibility=team`：团队成员可见。
- `visibility=private`：仅组织者 + 参与者可见。
- 非参与者：列表不返回，详情 404。
- 不使用前端 `if (private) hide` 作为唯一防线。

### 7.2 忙闲

非参与者只返回：

```json
{
  "start_at": "...",
  "end_at": "...",
  "all_day": false,
  "busy": true,
  "event_id": null,
  "title": null,
  "visibility": "private"
}
```

**不得返回**：`description`、`location`、`created_by`、`participants`、`color`。

### 7.3 冲突

非参与者的冲突项：

```json
{
  "user_id": 2,
  "display_name": "陈",
  "start_at": "...",
  "end_at": "...",
  "event_id": null,
  "title": null,
  "visibility": "private"
}
```

### 7.4 测试要求

- 断言响应 JSON 中不包含私密标题/地点/描述。
- 断言不是只断言 `title == null`，还要断言 key 不存在或值为 null（按契约）。
- 用不同用户 token 交叉请求。

## 8. 时间契约

- 存储：UTC。
- API：ISO 8601 UTC，带 `Z`。
- 团队时区：`teams.timezone`，默认 `Asia/Shanghai`。
- 前端显示：按团队时区；不直接 `new Date().toLocaleString()` 了事。
- 全天活动：`start_at=当天 00:00`、`end_at=次日 00:00`（团队时区）；`all_day=true`。
- 不使用无时区 `datetime.now()`；用 `now_utc()` 注入。
- 测试边界：23:30、00:00、跨月、跨年、闰日。

**禁止**：

- 把本地时间直接写库。
- 用字符串截断处理日期。
- 前端自己加 8 小时。
- 把全天活动存成 00:00–23:59（应为次日 00:00）。

## 9. WebSocket 契约

- 连接：`GET /api/v1/ws?token=<jwt>`。
- 无效 token：close `4401`。
- 客户端 30 秒 `{"type":"ping"}`；服务端 `{"type":"pong"}`。
- 消息：`{ "type": "...", "payload": {...}, "ts": "..." }`。
- 类型清单见 `docs/03` §7.2；不得新增未文档化类型。
- WS 只发“变了”的最小信息；客户端重取 HTTP。
- 私密活动：参与者收 `event.*`；其他成员收 `calendar.changed`（不带详情）。
- 客户端收到 `*.created/updated` 只做失效 + 重取，不直接拼数据。

**禁止**：

- 在 WS 里返回完整活动对象（两套序列化会漂移）。
- 用 WS 做写操作。
- 用 WS 替代通知落库。

## 10. 契约变更流程

任何 API/DB/WS 变更，按顺序：

1. 写 CR（`docs/ai/04`），说明动机、影响、替代方案。
2. 评估：影响哪些表/端点/页面/测试/演示。
3. 决策：批准/拒绝/延期；批准要指定负责人和截止。
4. 更新 `docs/03` 与 `docs/ai/02`。
5. 加迁移（DB）或版本说明（API）。
6. 更新前后端类型与调用。
7. 加契约测试/迁移测试。
8. 两人 review；合并后通知对方。

**没有 CR 的契约变更，review 直接拒绝。**

## 11. 契约测试

| 测试 | 内容 |
|---|---|
| OpenAPI 快照 | `openapi.json` 与基线 diff；新增字段需说明 |
| 响应 schema | 关键端点返回字段/类型/状态码 |
| 错误码 | 401/403/404/409/422 各至少 1 条 |
| 迁移 | 空库 → head；上一版 → head |
| 脱敏 | 非参与者响应不含私密字段 |
| 时区 | 23:30/00:00/跨月 |

OpenAPI 快照放 `server/tests/openapi_snapshot.json`；变更时更新并附 CR 编号。

## 12. AI 禁止清单

- ❌ 改端点路径/方法/字段名，而不改文档。
- ❌ 加 `GET /teams/{id}/dashboard` 之类“顺手”的端点。
- ❌ 把列表改成数组、把错误改成 200。
- ❌ 直接 `ALTER TABLE` / 手改 SQLite 文件。
- ❌ 在 router 里手写 `dict(event)` 绕过脱敏。
- ❌ 用 `team_id` 从请求体取，而不校验成员。
- ❌ 把 `private` 活动的标题放进忙闲响应。
- ❌ 把 token/密码写进日志。
- ❌ 为了前端方便，返回 `password_hash` 或内部字段。
- ❌ 在 WS 里加未文档化的 payload。

---

## 13. 一句话总结

**路径、字段、错误码、表结构、WS 类型都是冻结契约；要改就写 CR、改文档、加迁移、加测试。跑通不等于可以对，契约对才算完成。**
