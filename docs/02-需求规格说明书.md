## 1. 背景与目标

### 1.1 背景

学生团队和小型项目组通常用群聊约时间、用口头确认出席、用另一个工具记任务。结果是：

- 约时间要反复问，信息不同步；
- 谁去谁不去没有状态，组织者靠猜；
- 任务截止日不在日历上，容易漏；
- 换设备/换端后，日程对不上。

### 1.2 产品目标

做一个 **团队共享日历 + 轻量任务** 的协作工具，三端可用：

1. 团队日历：成员能看到团队活动和彼此可共享的忙闲。
2. 邀约闭环：创建活动 → 邀请 → RSVP → 变更通知。
3. 任务闭环：创建 → 指派 → 截止提醒 → 完成。
4. 实时同步：一端修改，其他端尽快看到。
5. 三端提醒：Web 站内、桌面系统通知、Android 本地通知。

### 1.3 成功标准

- 3 个演示账号在 5 分钟内完成“注册 → 建队 → 邀请码加入 → 建活动 → 邀请 → RSVP”。
- 周视图能看出成员忙闲；冲突活动有提示且可强制保存。
- 任务指派后，被指派人在另一端 2 秒内收到通知。
- 事件前 15 分钟桌面/Android 收到提醒。
- 非成员无法访问团队数据；私密活动详情不泄露。
- 断网重连后数据自动刷新，不丢已保存内容。

### 1.4 目标用户

- 3–20 人的学生课程组、社团项目组、小型创业团队。
- 成员有各自的学生邮箱/账号，不需要企业组织架构。
- 主要使用 Windows 桌面 + Android 手机；浏览器作为通用入口。

## 2. 用户角色与权限

### 2.1 角色

| 角色 | 说明 |
|---|---|
| 游客 | 未登录，只能注册/登录 |
| 成员 Member | 查看团队日历、建活动、邀请、管理自己的任务 |
| 管理员 Admin | 成员权限 + 管理团队资料、成员、邀请码 |
| 所有者 Owner | 创建者；管理员权限 + 删除团队/转让所有权 |
| 运维 | 非产品角色；部署、种子数据、备份 |

### 2.2 权限矩阵

| 操作 | Owner | Admin | Member |
|---|---|---|---|
| 查看团队日历/忙闲 | ✓ | ✓ | ✓ |
| 创建活动、邀请团队成员 | ✓ | ✓ | ✓ |
| 编辑/删除自己创建的活动 | ✓ | ✓ | ✓ |
| 编辑/删除他人创建的活动 | ✓ | ✓ | — |
| RSVP 自己收到的邀请 | ✓ | ✓ | ✓ |
| 查看参与者与 RSVP 状态 | ✓ | ✓ | ✓ |
| 创建任务、指派给成员 | ✓ | ✓ | ✓ |
| 编辑任务标题/截止/负责人 | ✓ | ✓ | 仅自己创建 |
| 修改任务状态 | ✓ | ✓ | 仅自己负责或创建 |
| 管理成员（移除/改角色） | ✓ | ✓（不能动 Owner） | — |
| 轮换邀请码 | ✓ | ✓ | — |
| 编辑团队资料 | ✓ | ✓ | — |
| 删除团队 | ✓ | — | — |
| 退出团队 | 需先转让/删除 | ✓ | ✓ |

### 2.3 权限规则

- **P-01** 所有团队资源必须先校验 `team_members.status = active`；非成员访问团队资源返回 404（不暴露团队是否存在）。
- **P-02** 已登录但角色不足（如 Member 编辑他人活动）返回 403。
- **P-03** Owner 唯一；Admin 不能移除/降级 Owner；Owner 不能直接退出，必须先转让或删除团队。
- **P-04** 私密活动的详情只对组织者和参与者可见；其他团队成员即使知道 id 也返回 404。
- **P-05** 前端隐藏按钮不能替代后端校验；所有权限必须在 API 层再校验一次。

## 3. 用例

### UC-01 注册与登录

**参与者**：游客  
**前置条件**：无  
**主流程**：

1. 游客打开 Web/桌面/Android，进入登录页。
2. 选择“注册”，填写用户名、显示名、密码（可选邮箱）。
3. 服务端校验用户名唯一、密码 ≥ 8 位，创建用户并返回 JWT。
4. 客户端保存 token，进入团队选择页。
5. 已注册用户输入用户名/密码登录；成功后同样进入团队选择页。
6. 重启应用后，客户端用本地 token 调用 `/auth/me`，有效则免登录。

**备选流程**：

- 1a. 用户已有 token 且有效 → 直接进入团队选择页。
- 2a. 注册时用户名重复 → 返回 409 `USERNAME_TAKEN`，提示换一个。
- 2b. 密码过短 → 前端即时提示，服务端返回 422。

**异常流程**：

- 3a. 登录密码错误 → 401 `INVALID_CREDENTIALS`，不区分“用户不存在/密码错”。
- 3b. 连续失败 5 次/分钟 → 429 `RATE_LIMITED`（P1）。
- 3c. token 过期 → 401，客户端清除 token 并跳登录页。

**后置条件**：用户已登录；本地有有效 token；服务端有用户记录。  
**关联需求**：AUTH-1..7。

---

### UC-02 创建团队并邀请成员

**参与者**：Owner、Admin、成员  
**前置条件**：已登录。  
**主流程**：

1. 用户在团队选择页点击“创建团队”，填写名称、描述。
2. 服务端创建团队，创建者成为 Owner，生成 8 位邀请码。
3. 用户复制邀请码发给同学。
4. 同学注册/登录后输入邀请码加入，成为 Member。
5. Owner 在成员列表看到新成员；可设置 Admin。
6. 成员可在团队切换器中切换多个团队。

**备选流程**：

- 4a. 重复输入同一邀请码 → 幂等返回当前成员身份，不报错。
- 5a. Owner 轮换邀请码 → 旧码立即失效，已加入成员不受影响。
- 5b. Owner 移除成员 → 该成员立即失去访问权；按 BR-13 处理任务/活动/通知：未完成任务变“待重新指派”，团队活动保留、Admin/Owner 接管，其私密活动取消，未读团队通知删除。

**异常流程**：

- 2a. 团队名称为空/超长 → 422。
- 4b. 邀请码错误/已轮换 → 409 `INVITE_CODE_INVALID`。
- 4c. 用户已是成员 → 返回 200 当前团队（幂等）。
- 5c. Admin 尝试移除 Owner → 403。

**后置条件**：团队成员关系建立；邀请码可复用直至轮换；成员列表与权限生效。  
**关联需求**：TEAM-1..10。

---

### UC-03 创建活动并邀请成员

**参与者**：组织者（任意成员）、被邀请人  
**前置条件**：已加入团队；已选定团队日历。  
**主流程**：

1. 组织者在月/周/日视图点击“新建活动”或空白时段。
2. 填写标题、开始/结束、全天、地点、描述、颜色、可见性。
3. 选择参与者（默认自己；可多选团队成员）。
4. 提交；服务端校验时间、成员身份、冲突。
5. 无冲突：创建活动，组织者自动 `accepted`，其他参与者 `pending`。
6. 返回活动详情；团队日历刷新；被邀请人收到通知。

**备选流程**：

- 4a. 有冲突 → 返回 409 `TIME_CONFLICT` + 冲突列表；前端弹窗展示。
- 4b. 用户选择“仍然创建” → 带 `ignore_conflicts=true` 重试，创建成功。
- 5a. 私密活动 → 只有组织者和参与者能看到详情；其他成员在忙闲中只看到“忙碌”。
- 5b. 补录过去的活动 → 允许创建，但不生成提醒；已开始的活动不可再改时间/地点。

**异常流程**：

- 3a. 结束时间 ≤ 开始时间 → 422 `INVALID_TIME_RANGE`。
- 3b. 参与者不是团队成员 → 422 `INVALID_PARTICIPANT`。
- 3c. 非成员调用 → 404。
- 4c. 全天活动跨天 → 按日期语义校验，结束日期 ≥ 开始日期。
- 4d. 活动已开始后修改时间/地点 → 422 `EVENT_ALREADY_STARTED`。

**后置条件**：活动入库；参与者关系建立；通知生成；日历与忙闲更新。  
**关联需求**：EVT-1..12、RSVP-1、AVAIL-3。

---

### UC-04 回应邀请（RSVP）

**参与者**：被邀请人、组织者  
**前置条件**：收到活动邀请。  
**主流程**：

1. 被邀请人从通知/活动详情进入。
2. 选择“接受/拒绝/待定”。
3. 服务端更新该参与者的 `response` 与 `responded_at`。
4. 组织者和其他参与者在详情中看到最新状态；组织者收到实时更新。
5. 被邀请人可再次修改，直到活动结束/取消。

**备选流程**：

- 2a. 被邀请人先“待定”，之后改“接受” → 允许。
- 2b. 被邀请人“拒绝”后想反悔 → 允许重新接受。
- 4a. 组织者修改时间/地点 → 已接受者收到变更通知，可重新确认（P1 强制重新确认）。

**异常流程**：

- 1a. 非参与者调用 → 私密活动 404（不可见）；团队活动 403（可见但非参与者）。
- 3a. 组织者尝试拒绝自己的活动 → 422；组织者应取消活动而不是拒绝。
- 3b. 活动已取消 → 409 `EVENT_CANCELLED`。
- 3c. 活动已结束 → 409 `EVENT_ENDED`；不再接受邀请/RSVP。

**后置条件**：RSVP 状态更新；组织者视图同步；冲突计算按最新状态调整（拒绝者不再计入）。  
**关联需求**：RSVP-1..6。

### UC-05 查看团队忙闲并避开冲突

**参与者**：团队成员  
**前置条件**：已加入团队；团队有活动。  
**主流程**：

1. 成员打开团队周视图，默认显示全部成员。
2. 前端请求 `GET /teams/{id}/availability?from&to`。
3. 服务端返回每位成员的忙碌块；私密活动只返回时间段与 `busy: true`。
4. 前端在周视图叠加忙闲层；点击空白格可新建活动并预填时间/参与人。
5. 保存时服务端再次检测冲突；有冲突则提示，用户可改时间或强制保存。

**备选流程**：

- 1a. 成员筛选“仅我” → 只显示自己的忙闲。
- 3a. 全天活动 → 显示为全天忙碌。
- 5a. 无冲突 → 直接创建。

**异常流程**：

- 2a. 日期范围 > 31 天 → 422。
- 2b. 非成员 → 404。
- 4a. 私密活动标题/地点/描述不得出现在非参与者响应中（验收硬条件）。

**后置条件**：成员能看到团队时间分布；冲突被提示而非静默忽略。  
**关联需求**：CAL-8、AVAIL-1..6、EVT-11/12。

### UC-06 创建与完成任务

**参与者**：创建者、负责人  
**前置条件**：已加入团队。  
**主流程**：

1. 成员在任务页点击“新建任务”。
2. 填写标题、描述、负责人、截止时间（必填）、优先级。
3. 服务端校验负责人是活跃成员，创建任务，状态 `todo`。
4. 任务出现在任务列表和日历截止行；负责人收到通知。
5. 负责人把状态改为 `doing`，完成后改为 `done`，记录 `completed_at`。
6. 创建者/Admin 可编辑标题、截止、负责人；可重新打开。

**备选流程**：

- 3a. 不指派负责人 → 422（MVP 必须指定；成员移除后的历史任务除外）。
- 4a. 截止时间已过 → 创建成功但立即标记逾期。
- 5a. 负责人误点完成 → 可重新打开。

**异常流程**：

- 2a. 截止时间为空 → 422。
- 2b. 负责人不是团队成员 → 422。
- 5b. 非负责人/非创建者/非 Admin 修改状态 → 403。
- 5c. 成员被移除 → 其未完成任务 `assignee_id = NULL`，显示“待重新指派”，通知 Admin。

**后置条件**：任务入库；日历截止行更新；通知生成；逾期状态可计算。  
**关联需求**：TASK-1..10。

### UC-07 接收通知与提醒

**参与者**：用户  
**前置条件**：已登录；有权限接收通知。  
**主流程**：

1. 事件邀请/变更/取消、任务指派/到期等触发通知，落库。
2. 在线用户通过 WS 收到 `notification.created`；离线用户下次登录拉取。
3. Web 显示角标与 toast；桌面弹系统通知；Android 由本地定时通知提醒。
4. 用户点击通知 → 打开对应活动/任务；标记已读。
5. 支持单条/全部已读；未读数实时更新。

**备选流程**：

- 3a. 用户关闭系统通知权限 → 只显示站内通知；设置页提示。
- 4a. 活动已删除 → 打开时提示“活动已取消”，不白屏。

**异常流程**：

- 2a. WS 断开 → 客户端重连；重连后拉取未读与当前视图。
- 3b. 同一提醒重复触发 → `dedupe_key` 唯一约束，只保留一条。

**后置条件**：通知可追溯；未读数正确；提醒不重复、不遗漏（在服务运行前提下）。  
**关联需求**：NOTI-1..9、RT-1..6。

### UC-08 三端使用

**参与者**：用户  
**前置条件**：已注册；对应端已安装/可访问。  
**主流程**：

1. **Web**：浏览器打开，登录，使用全部功能。
2. **Electron**：安装后打开，登录；关闭窗口最小化到托盘；收到提醒弹系统通知；点击通知聚焦并打开活动。
3. **Android**：安装 APK，登录；可查看/编辑日程；同步后为未来 7 天事件/任务安排本地通知；点击通知打开应用。

**备选流程**：

- 2a. 托盘退出 → 应用完全退出，不再提醒。
- 3a. 未授权通知 → 引导到系统设置；未授权时应用内仍可用。
- 3b. 应用被系统杀死 → 已安排的本地通知仍可触发；但服务端变更不会实时到达。

**异常流程**：

- 1a. 断网 → 提示“连接已断开”；只读；恢复后刷新。
- 2b. 服务端不可达 → 桌面端显示离线提示，不阻塞本地查看（MVP 无缓存，实际不可用则提示）。
- 3c. Android 12+ 精确闹钟受限 → 提示允许“闹钟和提醒”权限。

**后置条件**：三端使用同一账号、同一数据；平台差异有明确说明。  
**关联需求**：DESK-1..6、AND-1..6。

## 4. 功能需求

> 验收标准为最低要求；更细的测试步骤见 `docs/ai/05-验收与测试清单.md`。

### 4.1 账号与认证

| 编号 | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| AUTH-1 | 用户名 + 密码注册 | 用户名唯一；密码 ≥ 8 位；重复用户名 409；成功返回 JWT | P0 |
| AUTH-2 | 登录 | 正确凭据返回 token + user；错误 401；token 7 天有效 | P0 |
| AUTH-3 | 登出 | 客户端清除 token；再访问受保护接口 401 | P0 |
| AUTH-4 | 当前用户资料 | `GET /auth/me` 返回 id/username/display_name/avatar_color；可改昵称/颜色 | P0 |
| AUTH-5 | 修改密码 | 验证旧密码；新密码 ≥ 8 位；成功后旧 token 仍可用（MVP） | P1 |
| AUTH-6 | 登录态持久化 | 三端重启后，有效 token 免登录；过期跳登录页 | P0 |
| AUTH-7 | 登录限流 | 同 IP + 用户名 5 次/分钟；超限 429 | P1 |

**Given/When/Then 示例（AUTH-1）**

- Given 已存在用户名 `lin`；When 用 `lin` 注册；Then 返回 409 `USERNAME_TAKEN`，不创建用户。
- Given 密码 `1234567`（7 位）；When 注册；Then 返回 422，提示至少 8 位。

---

### 4.2 团队

| 编号 | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| TEAM-1 | 创建团队 | 创建者自动 Owner；返回 8 位邀请码；团队名 1–50 字 | P0 |
| TEAM-2 | 邀请码 | 唯一、可复制；轮换后旧码立即失效 | P0 |

## 5. 业务规则

### BR-01 团队隔离

- 每个团队的数据独立；用户可属于多个团队。
- 所有团队资源查询必须带 `team_id` 并校验成员身份。
- 跨团队访问统一 404（避免枚举）；角色不足 403。

### BR-02 角色与所有权

- Owner 唯一，创建者自动成为 Owner。
- Owner 可转让（P1）或删除团队；不能直接退出。
- Admin 可管理成员，但不能移除/降级 Owner。
- Member 可创建活动/任务，但不能管理团队。

### BR-03 活动可见性

- `team`：团队成员可见详情；出现在团队日历。
- `private`：组织者与参与者可见详情；其他成员在忙闲中只看到“忙碌”，不出现在团队活动列表。
- 私密活动的通知只发给组织者与参与者。

### BR-04 冲突语义

- 冲突 = 新活动时间段与某参与者已有活动重叠：`new.start < old.end AND new.end > old.start`。
- 计入冲突的旧活动：`status=confirmed`、未删除、该用户是组织者或参与者、且 `response != declined`。
- 全天活动计入冲突：与当天任何定时活动重叠时提示；仅提示，不阻止。
- 冲突是警告；`ignore_conflicts=true` 可强制保存。
- 编辑活动时排除自身。
- 活动开始后不可再改开始/结束时间与地点；取消仍允许。
- 允许补录过去的活动，但不再生成提醒。

### BR-05 RSVP 语义

- 四态：`pending/accepted/declined/tentative`。
- 组织者创建时自动 `accepted`；组织者不能拒绝自己的活动，只能取消。
- 被邀请人可反复修改；每次更新 `responded_at`。
- `declined` 不计入冲突；`pending/tentative` 计入。
- 活动取消后，RSVP 不再可改。
- 活动结束后，RSVP 不再可改；邀请也不再接受。

### BR-06 任务语义

- 一个任务一个负责人；创建时必须指定活跃成员。
- 截止时间必填；任务出现在截止日。
- 成员被移除：其未完成任务 `assignee_id = NULL`，显示“待重新指派”，通知 Admin。
- 任务不占用时间网格，不与活动做冲突检测。
- 逾期 = `due_at < now AND status != done AND deleted_at IS NULL`。

### BR-07 时间与全天

- 数据库存 UTC；API 用 ISO 8601 UTC；前端按团队时区显示。
- 团队时区默认 `Asia/Shanghai`；MVP 不支持用户级时区。
- 全天活动：`start_at = 当天 00:00`，`end_at = 次日 00:00`（团队时区）；`all_day=true`。
- 跨天定时活动按实际时间显示；月视图按开始日归属，周/日视图分段。
- 边界用例：23:30 开始、00:00 结束、跨月、跨年、闰日。

### BR-08 通知与去重

- 通知必须落库；WS 只是加速。
- `dedupe_key` 唯一：`{type}:{user_id}:{entity_id}:{bucket}`。
- 事件提醒 bucket = `15m`；任务即将到期 = `1h`；逾期 = 当地日期 `YYYY-MM-DD`。
- 同一提醒重复扫描不新增；不同日期可再次提醒。

### BR-09 删除与取消

- 活动“取消”：`status=cancelled`，通知参与者，保留记录。
- 活动“删除”：`deleted_at` 软删除，列表/详情不再出现；仅组织者/Admin。
- 任务删除：软删除；从列表/日历移除。
- 团队删除：软删除；成员立即失去访问；邀请码失效。
- 物理删除只由运维在备份后执行。

### BR-10 邀请码

- 8 位大写字母+数字；唯一；可轮换。
- 轮换后旧码立即失效；已加入成员不受影响。
- 邀请码不是权限凭证之外的身份凭证；加入仍需登录。

### BR-11 数据与备份

- SQLite 文件每日备份；保留 7 天。
- 备份包含用户、团队、活动、任务、通知；不含明文密码（只有哈希）。
- 恢复演练至少 1 次（W5）。

### BR-12 限制

- 单团队 ≤ 50 人；单用户 ≤ 20 团队；单团队 ≤ 10,000 活动。
- 事件查询跨度 ≤ 92 天；忙闲查询 ≤ 31 天。
- 标题 ≤ 100 字；描述 ≤ 2000 字；团队名 ≤ 50 字。
- 请求体 ≤ 1 MB；不支持附件上传。

### BR-13 成员移除后的数据归属

- 任务：未完成任务 `assignee_id = NULL`，显示“待重新指派”，通知 Admin。
- 该成员创建的团队可见活动：保留；组织者显示“已离开”；Admin/Owner 接管编辑；参与者与 RSVP 不变。
- 该成员创建的私密活动：自动取消（`status=cancelled`），通知参与者，不再展示。
- 该成员作为参与者的活动：`response` 置 `declined`，保留行；组织者可见；不再收到通知。
- 删除该成员在该团队的未读通知，避免点开 404。
- Owner 不能被移除；Owner 要退出必须先删除团队（转让所有权为 P1）。

### BR-14 并发编辑

- MVP 采用**最后写入生效**，不做字段级合并；除时间冲突外不返回 409。
- 活动/任务响应带 `updated_at`；前端发现本地基线早于服务端时提示“已被他人修改”，让用户刷新或覆盖。
- P1 可加 `ETag` / `If-Unmodified-Since` 乐观锁；当前不引入版本列。

| 活动详情 | `/app/teams/:id/events/:eventId` | 详情、参与者、RSVP、编辑/取消 |
| 任务 | `/app/teams/:id/tasks` | 列表、筛选、新建、完成 |
| 成员 | `/app/teams/:id/members` | 成员、角色、邀请码、移除 |
| 团队设置 | `/app/teams/:id/settings` | 名称/描述/时区、轮换邀请码、删除 |
| 通知 | `/app/notifications` | 列表、已读、跳转 |
| 个人资料 | `/app/profile` | 昵称/颜色、修改密码、退出 |

### 7.2 关键交互

- 日历空白格点击 → 新建活动，预填开始/结束。
- 事件点击 → 详情抽屉/弹窗；移动端全屏。
- RSVP 按钮：接受/待定/拒绝，当前状态高亮；提交后即时更新。
- 冲突弹窗：列出冲突成员与时段；“改时间”/“仍然创建”。
- 任务勾选完成 → 即时变绿；撤销通过“重新打开”。
- 通知点击 → 跳转并标记已读。
- 所有破坏性操作（删除团队/活动/任务、移除成员）二次确认。

### 7.3 状态与反馈

- 加载：骨架屏/Spinner；空状态有引导文案。
- 错误：表单字段级错误 + 顶部 toast；网络错误可重试。
- 离线：顶部条“连接已断开，正在重连…”；禁止写操作或提示失败。
- 权限：隐藏无权按钮，但后端仍校验；403 显示“没有权限”。
- 移动端：底部导航（日历/任务/通知/我的）；周视图可横滑。

### 7.4 视觉与可用性

- 日历优先：一屏内看到时间、成员、事件。
- 颜色有语义：事件按创建者/自定义；任务截止用中性色；逾期红色。
- 对比度 ≥ WCAG AA；所有图标按钮有 `aria-label`。
- 中文文案；时间格式 `MM-DD HH:mm`；全天显示“全天”。

## 9. 验收标准

### 9.1 P0 验收门禁

| 模块 | 必须通过 |
|---|---|
| 账号 | 注册/登录/登出/持久化；重复用户名 409；错误密码 401 |
| 团队 | 创建/邀请码加入/成员列表/角色/移除/退出/轮换；跨团队 404；移除按 BR-13 |
| 日历 | 月/周/日切换；成员筛选；今天/翻页；移动端可用 |
| 活动 | 创建/编辑/取消/删除；全天；私密脱敏；邀请幂等；开始后不可改时间；结束后不可邀请 |
| RSVP | 四态；反复修改；组织者汇总；拒绝者不计冲突；结束后不可改 |
| 忙闲 | 成员忙闲块；私密脱敏；全天；范围限制 |
| 冲突 | 检测/提示/强制保存；编辑排除自身 |
| 任务 | 创建/指派/完成/重开/逾期；截止行；移除成员后待指派 |
| 通知 | 列表/未读/已读；事件/任务通知；提醒去重 |
| 实时 | WS 鉴权/广播/重连/刷新；断网演练 |
| 三端 | Web 全功能；桌面托盘/通知；Android 本地通知 |
| 质量 | `make check` 全绿；E2E 3 条；覆盖率 ≥ 70%；部署可访问；关键路径两人复核 |

### 9.2 验收方式

1. **自动**：pytest、Vitest、Playwright、`make check`。
2. **手工**：三端清单（桌面/Android/Web），按 `docs/ai/05-验收与测试清单.md`。
3. **演示**：8 分钟脚本，从种子数据开始，连续跑两遍。
4. **审查**：权限、私密脱敏、时区、迁移、密钥。

### 9.3 退出标准

- 所有 P0 项通过，或未通过项有书面说明并经指导教师/两名项目成员同意。
- 无 P0 缺陷；P1 缺陷有记录，不影响核心演示。
- 部署环境可从零启动；种子数据可重置。
- 文档齐全：PRD、设计、用户手册、部署、验收、已知限制。

- 离线写入、CRDT/冲突合并。
- Google/Outlook 日历双向同步。
- 付费/订阅/发票。
