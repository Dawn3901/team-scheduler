---

## 2. 未完成的事实与原因

当前开发环境：

- Windows 上 `java -version` 为 **JDK 24.0.1**；
- 项目使用 Gradle 8.11.1 + Android Gradle Plugin 8.7.2，需要 **JDK 17/21**；
- 执行 `.\gradlew.bat assembleDebug` 报：

```text
BUG! exception in phase 'semantic analysis' in source unit '_BuildScript_'
Unsupported class file major version 68
```

`major version 68` 对应 Java 24，属于 JDK 版本不兼容。

同时：

- `ANDROID_HOME` 为空，常见路径下没有 Android SDK；
- 没有 `platform-tools` / `platforms;android-35` / `build-tools;35.0.0`；
- 没有生成 `app-debug.apk`。

已经发生的事实（2026-11-03，Capacitor 方案，保留为历史）：

- `pnpm sync:android`（脚本已移除）当时成功（Web 构建 + `cap sync android`，只证明 Web 资源复制成功）；
- `cap sync` 成功 **不等于** Android 能构建或能打开登录页；当前原生工程不再使用 cap sync。

## 3. 为什么允许带例外进入 W2

- 阻塞点是本机 Android 工具链（JDK/SDK），不是产品代码逻辑；
- W1 其余门禁已闭环：注册/邀请码/登录态/F5/404/403/契约/CI（PR #11 三 job success）；
- Electron 登录页已验证；
- Android 属于三端壳验证，不阻塞 W2 的日历/活动/RSVP 主线；
- 继续卡在环境安装上，会拖慢 W2 的 P0 验收。

**但这不等于 Android 已通过。** W1 状态记为“条件通过（带例外）”，W1-08 仍为“部分通过”。

### 4.1 完成步骤（2026-11-11 按原生工程更新）

> 下面的路径已改为当前 `apps/mobile/todolist` 原生 Kotlin WebView 工程；Capacitor 的 `apps/mobile/android` 与 `cap sync` 不再适用，仅保留在上文历史记录中。

1. 安装 JDK 17/21（Temurin/Microsoft OpenJDK），设置 `JAVA_HOME`；`gradlew --stop` 后重开终端。
2. 安装 Android SDK（工程 `compileSdk` 对应版本，当前 37）+ Platform-Tools；配置 `ANDROID_HOME` 或本地 `local.properties`。
3. 执行（任选其一）：
   ```bash
   pnpm android:build
   # 或
   cd apps/mobile/todolist && ./gradlew :app:assembleDebug
   ```
4. 产物：`apps/mobile/todolist/app/build/outputs/apk/debug/app-debug.apk`。
5. 安装到模拟器/真机，打开 App，确认能看到登录页；再验证 W4 通知权限与本地通知。
6. 保留证据：构建退出码、APK 路径、登录页截图/录屏；更新本文件与 W1 记录。
