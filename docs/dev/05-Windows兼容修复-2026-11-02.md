# Windows 兼容问题复核与修复 · 2026-11-02

## 输入与结论

依据用户提供的 Windows 测试报告 `测试.md`，并对当前 `feat/server-api` 代码复核。报告中的 Windows Chrome E2E 为 7/7，失败集中在备份、时区依赖及 Web 单测；不能概括为全部功能无法运行。

历史 Linux 验证记录不代表 Windows 验收。此前进度总结中的 `feat/server-web-p0` 是当时开发分支，本轮实际工作分支为 `feat/server-api`；没有改写历史执行记录。

## 修复

- `server/app/scheduler/backup.py`：SQLite Connection 的 `with` 只管理事务，不关闭连接。改为 `contextlib.closing`，在 rename/unlink 之前释放源库和临时库；只读 URI 改用 `Path.as_uri()`，正确处理路径空格等字符。
- `server/tests/test_collaboration.py`：备份测试自身的连接同样显式关闭，避免保留七份时被测试代码锁住旧备份。新增回归，在临时文件 rename 前通过实际数据库连接断言两个连接均已关闭；不依赖 Linux 允许重命名打开文件的行为。
- `server/pyproject.toml`：用户已明确授权添加 `tzdata>=2024.1; sys_platform == 'win32'`。Windows 新环境自动安装，Linux 通常使用系统时区库。测试回退路径时在本机额外安装 tzdata，并用空 `PYTHONTZPATH` 禁用系统时区库。
- `apps/web/src/test/utils.tsx`：统一卸载组件、取消查询、清理 QueryClient，防止请求或轮询跨用例残留。
- `apps/web/src/App.test.tsx`：路由组件测试不建立真实 WebSocket；实时行为仍由已有真实浏览器 E2E 验证。创建/加入团队后等待动态 import；创建团队标题断言在 `waitFor` 内重新查询，避免 Suspense 替换节点后对旧节点断言。未删除断言、跳过用例或提高测试超时。

报告中的“没有 mock 新接口/没有等待 lazy import”与当前代码不完全一致：已有新接口默认 mock 和部分 import 等待；本轮进一步修复的是清理顺序、真实 WS 干扰和 Suspense 节点替换竞态。

## Windows 更新和复测

在项目根目录使用 PowerShell：

```powershell
cd server
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe -m pytest -q
cd ..
pnpm --filter @teamsync/web test
pnpm --filter @teamsync/web test
pnpm --filter @teamsync/web test
pnpm test
make check
pnpm test:e2e
```

`make check` 需要 GNU Make 及项目约定的 shell 环境；若没有 make，分别执行后端 pytest/Ruff、`pnpm test`、`pnpm -r typecheck`、`pnpm -r lint`。不要复制 Linux `.venv` 或 `node_modules` 到 Windows，应在 Windows 安装。
