分层规则（与 [AGENTS.md §2](../../AGENTS.md) 一致）：

- 权限统一走依赖（未来的 `deps.py`：`require_member / require_admin / require_owner`）。
- 序列化脱敏放 schema/service，不靠前端隐藏。
- 前端不直接拼 API URL，走 `packages/shared/src/api`。
- 三端不复制业务逻辑；平台差异只放 `apps/desktop` / `apps/mobile`。

## 4. 请求链路

```text
浏览器
  │  fetch("/api/v1/...") 或 fetch("/health")
  ▼
Vite dev server :5173  ──/api、/health 代理──▶  FastAPI :8000
                                                │
                                                ├─ CORS（生产直连时）
                                                ├─ router：参数校验 + Depends(get_db)
                                                ├─ service：业务规则 / 权限 / 脱敏
                                                ├─ SQLAlchemy Session
                                                ▼
                                          SQLite（WAL）
```

- 开发期前端走 Vite 代理（`apps/web/vite.config.ts`），所以浏览器看到的是同源请求，不需要处理 CORS。
- `packages/shared/src/api/client.ts` 的 `request()` 默认 base 是 `/api/v1`；`/health` 是基础设施接口，显式传空 base。
- WS 与 APScheduler 都跑在同一个进程内。**不要给 uvicorn 加多 worker**，否则连接表/调度器会各进程一份。

## 5. 后端约定

### 5.1 配置

```python
# server/app/config.py
ROOT_DIR = Path(__file__).resolve().parents[2]   # 仓库根目录
SERVER_DIR = Path(__file__).resolve().parents[1] # server/，SQLite 相对路径的基准
```

- 读取顺序：进程环境变量 > 仓库根目录 `.env`。`server/.env` 不会被读取。
- `SECRET_KEY` 没有默认值，避免用默认密钥启动。`make setup` 会在缺少 `.env` 时调用 `scripts/init_env.py`，从 `.env.example` 生成并写入随机 `SECRET_KEY`；已有 `.env` 不会被覆盖。
- 缺 `SECRET_KEY` 时，`get_settings()` 会抛带操作指引的 `RuntimeError`（提示运行 `python scripts/init_env.py`），而不是直接暴露 Pydantic 堆栈。
- `DATABASE_URL` 默认是相对路径 `sqlite:///./data/teamsync.db`；`resolve_database_url()` 会把相对 SQLite 路径固定解析到 `server/`，**不再依赖启动目录**。绝对路径和 `:memory:` 原样保留。
- `TEAM_TIMEZONE` 供业务层使用；`ACCESS_TOKEN_EXPIRE_DAYS` 供 W1-05 认证使用。
- `LOG_LEVEL` 和 `API_V1_PREFIX` 目前**没有被使用**：日志系统尚未配置，路由也还没挂到 `/api/v1`。加日志/路由时一起接上。

### 5.2 数据库会话

```python
def get_db() -> Generator[Session, None, None]:
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

- router 通过 `Annotated[Session, Depends(get_db)]` 注入，不要在 router 里自己 `SessionLocal()`。
- SQLite 连接建立时执行 `foreign_keys=ON`、`journal_mode=WAL`、`busy_timeout=5000`。
- `expire_on_commit=False`：commit 后对象仍可读，序列化前不用再查一次。
- 测试通过环境变量在导入前替换 `DATABASE_URL`；不要试图在测试里改 `settings.database_url`，engine 已经创建。

### 5.3 统一错误体

所有业务错误返回：

```json
{ "code": "NOT_FOUND", "message": "资源不存在", "details": {} }
```

- 业务异常优先抛 `ApiError(status_code, code, message, details)`；code 必须来自 [docs/ai/02 第 4 节](../ai/02-接口与数据契约.md)，不得改名。
- `RequestValidationError` 统一转成 **400 `VALIDATION_ERROR`**，只回传 `loc/msg/type`，不回显 `input`；业务语义错误用 **422 + 具体 code**（D16）。
- `HTTPException` 兜底会透传 `exc.headers`（如 405 的 `Allow`、429 的 `Retry-After`）。
- `HTTP_ERROR_CODES` 覆盖 400/401/403/404/405/409/422/429/500；领域错误优先用 `ApiError`，避免落到通用 `HTTP_ERROR`。
- 未捕获异常返回 500 `INTERNAL_ERROR`，日志只记录方法 + 路径，不打印请求体/Authorization。

### 5.4 路由与模型

- router 只做：路径/查询/请求体校验、依赖注入、调用 service、返回 schema。
- 新增团队资源时，必须同时校验 `team_id` 与成员身份；非成员统一 404，角色不足 403。
- 私密活动必须走统一序列化函数，不能手写 `dict(event)`。
- 新表只通过 Alembic 迁移创建；`models.py` 里的模型必须被 `migrations/env.py` 导入（现在导入的是 `app.models`）。
- 时间一律 UTC 存储；不要写无时区的 `datetime.now()`，用 `app.models.now_utc()`（返回 UTC aware datetime）。

**W1-04 已建模型**：

| 模型 | 表 | 关键约束 |
|---|---|---|
| `User` | `users` | `username` 唯一；`email` 可空但唯一 |
| `Team` | `teams` | `invite_code` 唯一；`owner_id` → `users.id`；`deleted_at` 软删除 |
| `TeamMember` | `team_members` | `(team_id, user_id)` 唯一；`role/status` CHECK；每队仅一个 `active` owner（部分唯一索引） |

- `team_members.user_id/team_id` 为 `ON DELETE CASCADE`；删除团队/用户会级联删除成员行。
- 建团队必须与 Owner 的 `team_members` 行在同一事务写入（工厂 `create_team()` 已按此约束造数）。

### 5.5 迁移

```bash
cd server
# Windows
.venv/Scripts/python.exe -m alembic revision --autogenerate -m "add users teams team_members"
.venv/Scripts/python.exe -m alembic upgrade head
# Linux / WSL / macOS
.venv/bin/python -m alembic revision --autogenerate -m "add users teams team_members"
.venv/bin/python -m alembic upgrade head
```

注意事项：

- 生成后**逐行 review**：SQLite 的 `render_as_batch=True` 已配置，但 autogenerate 仍可能漏索引/约束。
- 表/字段变化必须同步 [docs/03](../03-概要设计说明书.md) 与 [docs/ai/02](../ai/02-接口与数据契约.md)；契约变更先走 CR。
- 不要手改已有迁移；新增迁移修正。
- 提交前在空库上跑一遍 `upgrade head`，再跑 `downgrade`（若写了）和 `upgrade`。
- 开发库在 `server/data/teamsync.db`（含 `-wal` / `-shm`）；需要重置时先停服务再删这三个文件，然后 `alembic upgrade head`。

## 6. 前端约定

### 6.1 共享包

`packages/shared` 是**纯 TS 源码包**，`exports` 直接指向 `src/index.ts`，由 Vite/tsc 负责编译，没有独立 build 产物。

- 类型放 `src/types.ts`；请求函数放 `src/api/`；不要在各端重复定义。
- 前端只通过 `request()` 发请求，不在组件里 `fetch` 拼 URL。
- `request()` 会自动带 `Authorization: Bearer <token>`（token 存 localStorage，键名 `teamsync.token`）。
- 错误统一抛 `ApiError`（含 `status / code / message / details`）；UI 根据 `code` 分支，不要匹配 message 文本。
- 当前 `request()` 没有超时、没有全局 401 处理；加认证时一起补（审查报告 R-11）。

### 6.2 Web

- 路由尚未引入（当前只有单页占位）。加 React Router 属于技术选型，先确认。
- 样式是手写 CSS（`styles.css`）；Tailwind 尚未安装，不要直接写 Tailwind 类。
- 状态管理目前是组件内 `useState`；TanStack Query / Zustand 是规划项，不要提前引入第二套模式。
- 开发代理在 `vite.config.ts`：`/api` 与 `/health` 都转发到 `127.0.0.1:8000`。改后端端口要同步改这里。
- 页面必须覆盖加载 / 空 / 错误三态；破坏性操作二次确认；移动端 375px 宽可用。

### 6.3 时间

- 后端返回 UTC ISO 8601；前端用共享日期工具按团队时区显示（`date-fns` 待引入）。
- 全天活动：团队时区当天 00:00 → 次日 00:00，`all_day=true`。
- 跨天活动按实际时间显示；月视图按开始日归属，周/日视图分段。
- 前端不要自己做 `new Date()` 加减时区；统一走日期工具。

### 9.2 写测试的硬要求

- 新逻辑同时写测试；修 bug 先写复现用例；不通过删/跳过测试变绿。
- 不 mock 权限、冲突、脱敏、提醒这些核心逻辑。
- 每个团队资源至少一条“跨团队访问”测试；私密活动至少一条“非参与者拿不到标题”测试。
- 时间用例覆盖 23:30、00:00、全天、跨天、跨月。
- 错误码用例覆盖 401/403/404/409/422（见 `docs/ai/02` 契约测试矩阵）。
- 测试数据用工厂，不用生产数据；不要依赖测试执行顺序。

### 9.3 当前测试基础设施的坑

- `app.db` 的 `engine` 在导入时创建，`conftest.py` 只能靠“先设环境变量再导入”隔离；新增 fixture 时不要在测试内部改 `DATABASE_URL`。
- 建表 fixture 已建立：`_test_database` 在会话开始时 `create_all`，`_clean_database` 在每个用例后清空业务表；测试数据统一走 `server/tests/factories.py`，不要在用例里手写整行 dict。
- `db` fixture 是直接可用的 Session；工厂函数默认 commit，因此后续 API 测试里 `TestClient` 的独立 Session 也能读到数据。
- 迁移测试在子进程里用独立临时库跑，避免 `get_settings()` / `engine` 的导入期缓存；不要把迁移测试改成对主测试库 `downgrade`。
- `TestClient` 默认会重新抛出未捕获异常；要测 500 handler，用 `TestClient(app, raise_server_exceptions=False)`。

### 9.4 CI

`.github/workflows/ci.yml` 两个 job：

- 后端：`ruff check .` → `pytest` → `alembic upgrade head`。
- 前端：`pnpm install --frozen-lockfile` → `pnpm -r typecheck` → `pnpm -r lint` → `pnpm --filter @teamsync/web build`。

CI 的 Python 依赖没有锁文件，pnpm 版本写死在 workflow 而根 `package.json` 没有 `packageManager` 字段（审查报告 R-08）。改依赖版本时两边一起看。

## 10. 常见改动流程

### 10.1 新增一个 API

1. 找到需求编号（`docs/02`），确认 P0、验收标准、错误码。
2. 若改路径/字段/状态码：先写 CR，更新 `docs/03` + `docs/ai/02`。
3. 在 `routers/` 加路由；业务规则放 `services/`；请求/响应 schema 放 `schemas/`（待建立）。
4. 补测试：成功、校验失败、权限不足、跨团队、私密脱敏（按接口性质取）。
5. 更新 `packages/shared` 类型与请求函数。
6. 前端接入，覆盖加载/空/错误。
7. `make check` + 迁移 + 手工验证；报告里写命令与结果。

### 10.2 新增一张表

1. CR / 设计评审通过，更新 `docs/03` 与 `docs/ai/02`。
2. `models.py` 加模型；确保被 Alembic 导入。
3. `alembic revision --autogenerate`，review 生成脚本（索引、外键、软删除列、时区列）。
4. 空库 `upgrade head`；再 `downgrade` / `upgrade` 验证。
5. 加迁移测试 / 约束测试。
6. 同步种子脚本（W1-09 后）。

### 10.3 改错误码

错误码是契约，**不得静默修改**：

1. 写 CR，说明影响的前端分支、测试、文档。
2. 更新 `docs/ai/02` 错误码表与 `docs/03`。
3. 改服务端 + 共享类型/调用方。
4. 加/改契约测试（至少覆盖新旧行为）。
5. 两人 review。

### 10.4 加页面

1. 对照 `docs/02 §7.1` 的页面清单与路由。
2. 先确认路由方案（尚未引入）；不要自创 URL 层级。
3. 复用 `packages/shared` 类型与 `request()`；不要复制业务规则。
4. 覆盖空/加载/错误/无权限四态；移动端 375px 走查。
5. 加组件测试或 E2E（测试框架建立后）。

## 11. 配置项

| 变量 | 默认 | 说明 |
|---|---|---|
| `SECRET_KEY` | 无（必填） | JWT 签名密钥；生产用 ≥32 字节随机值；禁止提交真实值 |
| `DATABASE_URL` | `sqlite:///./data/teamsync.db` | 相对路径按 `server/` 解析，与启动目录无关 |
| `CORS_ORIGINS` | `http://localhost:5173` | 逗号分隔；生产改成实际前端域名 |
| `TEAM_TIMEZONE` | `Asia/Shanghai` | 团队默认时区；MVP 不支持用户级时区 |
| `ACCESS_TOKEN_EXPIRE_DAYS` | `7` | token 有效期 |
| `LOG_LEVEL` | `INFO` | **尚未接入日志系统** |

`.env.example` 是模板；`.env` 已被 gitignore。新增配置项要同时更新 `.env.example`、本表、`config.py` 和部署文档。

## 12. 调试

- **健康检查**：`curl http://127.0.0.1:8000/health` → `{"status":"ok","db":"ok"}`；503 表示 DB 打不开。
- **OpenAPI**：启动后访问 `http://127.0.0.1:8000/docs` 或 `/openapi.json`。
- **数据库**：`sqlite3 server/data/teamsync.db '.tables'`；没有 sqlite3 CLI 时用 Python：
  ```bash
  cd server
  .venv/bin/python -c "import sqlite3;print(sqlite3.connect('data/teamsync.db').execute('select name from sqlite_master').fetchall())"
  ```
- **迁移状态**：`alembic current`、`alembic history`。
- **CORS**：开发期优先用 Vite 代理（同源）；直连 8000 时把来源加到 `CORS_ORIGINS` 并重启后端。
- **端口占用**：`lsof -i :8000` / `netstat -ano | findstr :8000`；不要同时跑两个 uvicorn 写同一个 SQLite。
- **SQLite 锁**：确认没有第二个后端进程；WAL 下读不阻塞写，但写仍串行。
- **Windows 控制台中文乱码**（迁移日志）：`chcp 65001`，或设置 `PYTHONUTF8=1`。
- **日志**：目前只有 uvicorn 默认日志 + 未捕获异常 `logger.exception`；`LOG_LEVEL` 尚未生效。加日志时不要打印密码、Authorization、完整 token。

## 14. 已知缺口

按优先级：

1. **契约**：400/422 口径已于 2026-10-31 定案（400 格式 / 422 语义），409/422 兜底与 `HTTPException` headers 已修；剩余 OpenAPI 快照与业务端点契约测试（随 W1-04 起补）。
2. **测试**：基础设施契约矩阵 + W1-04 表结构/迁移测试共 36 条；跨团队、脱敏、时区测试仍待业务功能。
3. **配置健壮性**：SQLite 相对路径已固定到 `server/`；R-06 已修（`make setup` 生成 `.env`，缺密钥时给操作指引）；`LOG_LEVEL`、`api_v1_prefix` 仍未接线。
4. **CI 可复现性**：Python 依赖未锁；pnpm 版本两处维护；无覆盖率门禁（R-08，建议 W1 内收口）。
5. **功能未开始**：认证（W1-05）、团队、日历、活动、RSVP、忙闲、任务、通知、WS、调度、三端、种子数据。
