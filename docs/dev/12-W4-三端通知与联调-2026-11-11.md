## 3. Electron

### 3.1 行为

- 启动创建托盘：显示主窗口 / 隐藏到托盘 / 退出；点击托盘切换显示。
- 关闭窗口不退出，隐藏到托盘；`before-quit` 后真正退出。
- 渲染进程只对 `event.reminder`、`task.due_soon`、`task.overdue` 调 `window.desktop.notify`。
- 主进程校验来源为主窗口、截断标题/正文、id 只收正整数；`Notification.isSupported()` 为 false 时跳过。
- 点击通知：显示窗口 → 发 `teamsync:navigate` → Web 打开活动详情或任务页 `?task=`。

### 3.2 验证

```bash
pnpm --filter @teamsync/desktop build
cd apps/desktop && ./node_modules/electron/dist/electron.exe . --disable-gpu --smoke-test --smoke-notify
```

输出：

```text
NOTIFY_IPC title=TeamSync 冒烟通知
NOTIFY_SUPPORTED=true
NAVIGATE_OK=true
SMOKE_OK url=app://teamsync/login loginPageRendered=true tray=true trayError= bridge={"notify":"function","navigate":"function"} trayToggleHidden=true trayToggleShown=true
```

说明：`NOTIFY_IPC` 证明渲染进程 → 主进程链路与 Notification API 可用；`NAVIGATE_OK` 证明主进程
`teamsync:navigate` 能被 preload 接收；**实际 Windows 通知气泡是否显示仍需人工确认**（本机冒烟窗口不等待用户点击）。

> **端到端注意（2026-11-11）**：`pnpm dev:desktop` 当前加载 `app://teamsync` 的构建产物，`main.ts` 只映射静态文件，**没有 `/api` 反向代理**；直接用它登录/收实时通知会失败。W4 手工验证请先 `make dev` 启动 Vite 5173，再用
> `electron . --web-url=http://127.0.0.1:5173` 启动壳。打包模式（`app://`）要补 API/WS 代理，属于 W5 缺口，不能把当前冒烟当成桌面端到端已通。

## 4. Android

### 4.1 方案

当前 `apps/mobile/todolist` 是原生 Kotlin WebView，不是 `docs/00` 基线里的 Capacitor。W4 不迁移框架，直接在现有壳上补：

- `TeamSyncAndroid.schedule(teamId, kind, payload)`：整批替换该 team+kind 的未来 7 天提醒；
- `cancel(teamId)`、`permission()`、`requestPermission()`；
- `NotificationScheduler`：AlarmManager 精确排程；无 `SCHEDULE_EXACT_ALARM` 时降级 `setAndAllowWhileIdle`；
- `NotificationReceiver`：到点展示通知，点击带 `path` 打开活动/任务；
- `BootReceiver`：重启后从 SharedPreferences 恢复未来项；
- `AndroidManifest.xml`：`POST_NOTIFICATIONS`、`SCHEDULE_EXACT_ALARM`、`RECEIVE_BOOT_COMPLETED`、`singleTop`。

### 4.2 Web 排程策略（有单测）

`buildAndroidSchedule`：

- 活动：`confirmed` 且 `my_response` 不是 null/declined；开始前 15 分钟；
- 任务：未完成且 `assignee_id === 当前用户`；截止前 1 小时；
- 只排未来 7 天；已过去的时间点不补发；
- id 含 `start_at`/`due_at`，改期后 id 变化；
- 按 `teamId + kind` 整批替换，避免重复提醒。

### 4.3 未验证

本机 `java`/`kotlinc`/Android SDK 均不可用，**没有执行**：

```bash
cd apps/mobile/todolist && ./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

因此 Android 侧只完成代码与静态审查；G4 的“Android 为未来 7 天事件安排本地通知；修改事件后重排”必须真机/模拟器复核。

## 6. W4-09 断网 30 秒演练

```bash
WSLENV=RECONNECT_OFFLINE_MS RECONNECT_OFFLINE_MS=30000 \
  "/mnt/c/Program Files/nodejs/node.exe" node_modules/@playwright/test/cli.js test --grep "断网恢复"
```

结果：

```text
ok 1 [msedge] › e2e\collaboration.spec.ts:299:5 › 断网恢复后重新连接并刷新 (33.5s)
1 passed (43.0s)
```

演练内容：浏览器网络隔离 30 秒 → 页面显示“连接已断开，正在重连…” → 恢复网络 → WS 自动重连、查询失效刷新、提示消失。

限制：这是浏览器网络隔离，不等同于“杀掉后端进程 30 秒”。进程级停服需按下面步骤人工补一次：

1. 启动后端 + Web，两个浏览器登录同一团队；
2. 停后端 30 秒，确认两端都显示断线提示；
3. 重启后端，最多等 30 秒退避，确认自动重连并刷新；
4. 记录两端恢复耗时与截图，补进本文件。

## 8. 风险与后续

1. **Android 方案需 A/B 确认**：原生 WebView 与 `docs/00` 的 Capacitor 基线不一致；若决定回 Capacitor，需要 ADR/CR 并整体替换现有壳，不能两套并存。
2. **Android 代码未编译**：Kotlin/Manifest 只做静态审查；首次在 Android Studio 打开时优先修编译错误，再谈真机。
3. **精确闹钟权限**：Android 12+ 用户可能未授权 `SCHEDULE_EXACT_ALARM`，当前降级为非精确；演示前在系统设置里确认“闹钟和提醒”已允许。
4. **Electron 打包**：`electron-builder` 未接入，`assets/tray.png` 尚未配置进安装包；W5/W6 打包时补。
5. **系统通知弹窗未人工确认**：冒烟只证明 IPC/Notification API 可用，不证明 Windows 通知中心实际展示。
6. **W4-09 进程停服未执行**：自动化只覆盖浏览器网络隔离；需要人工补一次停后端 30 秒的记录。
