## 数据与范围

- 500名虚构员工、10个50人部门，全员团队加部门团队共11个。
- 9822场活动、79400条参与记录、5061项任务和8089条依赖。
- 全员团队含5000项任务、8039条依赖及1200层链；每部门另有6步可读流程。
- 预置周会12次、双周评审8次，500人战略会含四种回应状态，私密安排用于推荐脱敏检查。
- 基准周为2026-11-16，随机种子20261109。所有人名、邮箱、公司均为虚构数据。
- **50人是产品现有加入团队上限**。500人全员团队直接写入测试夹具，只用来测试越界规模，不修改加入人数规则，也不宣称已有企业容量支持。
- 单团队10000活动上限保持，预留空间测试新增/批量创建。

## 运行与数据隔离

在仓库根目录：

```bash
server/.venv/bin/python -m scripts.company_demo seed
server/.venv/bin/python -m scripts.company_demo verify
server/.venv/bin/python -m scripts.company_demo serve --port 8018
```

前端单独终端：

```bash
cd apps/web
VITE_API_TARGET=http://127.0.0.1:8018 node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5186 --strictPort
```

独立数据库 `debug/company-demo-500/company.db`，从未切换或迁移日常库。造数拒绝覆盖。验证用SQLite backup API复制到临时目录，所有测试写入都发生在副本；演示库不被自动测试改动。原始造数的约10000场活动版本触发了现有活动上限，最终版本改为9822场，为正常业务验证预留容量，未改上限。

单机串行进程内TestClient，含HTTP路由、鉴权、序列化与SQLite，不含网络传输和浏览器渲染。以下均为一次观测，不是p95或吞吐量。

| 查询 | ms | SQL | 响应字节 |
|---|---:|---:|---:|

| /teams/1/availability/suggestions | 2508.08 | 6 | 6499 |
| /teams/1/tasks/dependency-graph | 6489.05 | 5005 | 945921 |

大图接口为明显N+1：`graph_out`对每个节点调用`summary/parents`，5000任务产生约5000条附加查询。推荐30天的候选扫描也明显变慢。后续可优先批量读取依赖与前置状态、限制图规模或按项目展示，以及优化候选区间扫描。此次按测试范围保留现状，未直接改组员业务代码。
