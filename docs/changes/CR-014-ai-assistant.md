# CR-014：可拖动 AI 日程助手

日期：2026-11-16。状态：用户在当前聊天明确要求实现 AI 助手、读取待办、创建活动并使用 DeepSeek 测试；本次按此授权实现必要的新增接口与配置。人类代码评审、最终验收仍待项目成员完成。

需求：AI-1（扩展，关联 TASK-6、EVT-1、EVT-7、EVT-11、CAL-7）。

- 登录后的所有 Web 页面提供浮动助手；鼠标/触屏拖动按钮或标题栏，限制在窗口内，支持收起、隐藏、顶部恢复，记住位置与隐藏偏好。
- 团队页面自动绑定当前团队，其他页面手动选择已加入团队。切换团队清空会话，登出卸载会话。聊天正文仅保存在当前组件内存中。
- 服务端校验活跃成员后读取当前团队未完成任务（最多100条）、未来31天可见活动（最多100条）以及活跃成员姓名；数据不足/截断明确标记，不包含其他团队、其他人的个人日历或不可见私密详情。
- 对话及上述业务数据会发送至配置的 AI 服务商，页面发送前告知。模型只回答和提出活动草稿，不直接写库。信息不足时优先合理补齐可调整草稿；“你选”等授权下默认晚上19:00、60分钟，日期未给默认明天，回复说明假设。成员歧义仍追问，不能伪称完成操作。
- 用户检查标题、日期、时区、地点、可见性和邀请成员后点击确认，调用既有活动创建 API；继续走成员校验、冲突检测、邀请、提醒与实时广播。冲突时显式选择强制创建或放弃草稿。确认动作不依赖模型自述。
- API：POST `/api/v1/teams/{team_id}/assistant/chat`，请求 `{messages:[{role:"user"|"assistant",content:string}]}`，1–20条，每条1–4000字符，最后一条须为用户消息。响应 `{answer:string,draft:EventInput|null}`，draft 无 recurrence/ignore_conflicts，起止时间规范为UTC。模型输出重新校验，参与者必须为当前活跃成员。
- 新错误：503 `AI_UNAVAILABLE`（未配置、网络/鉴权/余额问题、格式异常），不返回供应商响应或异常文本。沿用401/404/400/422业务错误。固定服务端地址，不允许浏览器指定供应商地址/Key/系统提示词。
- 配置：`OPENAI_API_KEY`（SecretStr，仅本地 .env）、`OPENAI_BASE_URL`（默认 https://api.deepseek.com）、`OPENAI_MODEL`（默认 deepseek-chat）。标准库 urllib 请求，无新增依赖，无表/迁移，无认证授权模型变更，无原生端配置变更。
- 影响：新增服务、路由、shared client、Web浮窗与测试；更新需求/设计/接口契约/README。属于新增需求，不改写冻结决策。实现不需要修改六周已完成历史记录。
- 测试：跨团队404、不登录401、私密活动过滤、模型格式失败、缺失Key/网络失败脱敏、草稿不写库、UTC跨日/跨月、活动确认冲突、前端对话/确认/隐藏/拖动流程。
- 限制：非流式；供应商请求45秒超时，客户端60秒；每次带最近对话，最多20条；只处理当前团队上述上下文范围，不支持AI修改/删除/完成任务、个人活动创建、附件、联网搜索、跨团队汇总和持久聊天。
- 成本：每次发送调用一次供应商，max_tokens=2000；多人公网使用前需另行评估配额/频控。本次不改变既有限流策略。
- 回滚：移除助手入口与路由、配置字段；无数据库回滚。可清空本地 `OPENAI_API_KEY` 暂停模型调用，原有功能继续可用。
- 演示：打开助手→询问“我的待办有哪些”→要求明天下午一小时会议→核对草稿→确认→查看活动；不替代原8分钟P0验收。
