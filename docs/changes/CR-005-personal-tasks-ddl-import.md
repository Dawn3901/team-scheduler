## 1. 背景

CR-002 解决的是“个人日程”。学生还有另一类数据：作业/实验/报告的 DDL。它更适合做成任务（可完成、可逾期、可筛选），而不是日程。

当前 `tasks` 是团队级的，所有成员可见。把个人 DDL 导入团队任务会带来隐私和噪音问题：

- 队友看到你所有作业；
- 个人任务和团队任务混在一起；
- 退队/换队后个人数据丢失。

因此需要**用户级个人任务**，再在其上做 DDL 导入。DDL 导入只接受文件/粘贴，不保存 LMS 账号密码、不服务端爬取。

---

## 2. 变更内容

### 2.1 目标

- 新增用户级 `personal_tasks`：跨团队、仅 owner 可见。
- 新增“我的任务”视图，或并入“我的日程”的任务区。
- 支持粘贴/CSV 导入 DDL：预览、去重、批量提交、撤销。
- 不做 LMS 自动同步、不保存凭据、不爬页面。
- 个人任务与团队任务完全隔离；团队任务语义不变。

### 2.2 本期范围（若批准）

| 项 | 内容 |
|---|---|
| 数据 | 新表 `personal_tasks` + Alembic 迁移；不改现有 `tasks` |
| API | `GET /me/tasks`、`POST/PATCH/DELETE /me/tasks`、DDL 导入预览/提交/撤销 |
| 权限 | 仅 owner；他人访问 404；不出现在团队任务列表 |
| 前端 | “我的任务”列表/编辑；导入向导 |
| 导入 | 粘贴文本/CSV；预览、幂等、批次撤销；不接 LMS |
| 提醒 | v1 不做个人任务提醒；只显示逾期；提醒另立 CR |
| 测试 | 个人任务 CRUD 隔离、导入幂等/撤销、截止时间/时区、P0 回归 |

### 2.3 明确不做

- **不做 LMS 账号对接/爬取**：不保存学生密码；不做乐学自动同步。
- **不做个人任务提醒**：避免与团队提醒、时区去重耦合；后续单独评估。
- **不做个人任务分派/协作**：个人任务只属于 owner；团队协作仍用团队任务。
- **不做子任务/多负责人/依赖**：TASK-9/10 仍是 P1，另立 CR。
- **不做双向同步/自动刷新**：v1 只支持单次文件/粘贴导入。
- **不做插件运行时**：内置可选模块即可。

### 2.4 与团队任务的区别

| 项 | 团队任务（现有） | 个人任务（本 CR） |
|---|---|---|
| 归属 | `team_id` | `user_id` |
| 可见性 | 团队成员 | 仅 owner |
| 负责人 | 团队活跃成员 | 固定为 owner |
| 通知 | 指派/截止/逾期 | v1 无提醒，仅逾期标识 |
| 用途 | 团队协作 | 个人 DDL/待办 |

## 4. 替代方案

### A. DDL 导入为团队任务（无新表）

- 导入到团队 `tasks`，指派给自己。
- 优点：2–3 人日，复用现有任务。
- 缺点：队友可见所有 DDL；多团队重复；退队丢失；个人/团队任务混杂。
- 适合：明确团队愿意共享作业清单的课程项目组。

### B. 只做个人任务，不做导入

- 手工创建个人任务。
- 优点：模型简单，4–5 人日。
- 缺点：DDL 多时录入成本高；学生场景吸引力弱。

### C. 个人任务 + 文件/粘贴导入（本 CR 推荐，若做）

- 新增 `personal_tasks`，导入走文件/粘贴。
- 优点：隐私清晰、可承载 DDL、退队不丢。
- 缺点：6–8 人日；两张任务表；测试面增加。

### D. 服务端对接乐学

- **拒绝**：凭据、ToS、页面易变；不作为课程项目方向。

### E. 并入个人日历，不做任务

- 把 DDL 建为全天个人日程。
- 优点：复用 CR-002，零新表。
- 缺点：不能标记完成/逾期；失去任务语义。
- 适合：只想“日历上看到 DDL”的轻量需求。

---

## 5. 取舍

**如果做：**

- 6–8 人日，需要新表和两张任务表的维护成本；
- 必须与 CR-002 一起设计导航/“我的”空间，否则页面碎片化；
- 个人任务提醒不做，用户可能期望；需在 UI 说明；
- 演示可加“粘贴 DDL → 我的任务”，但不挤占 P0。

**如果不做：**

- DDL 继续留在乐学/课程平台，团队日历只覆盖会议/活动；
- 个人日历（CR-002）仍可手工记录截止日；
- 产品保持“轻量团队任务”，范围更稳。

**建议：**

- 当前**暂缓**；先完成 CR-002 个人日历和 CR-006 找空闲；
- 如果学生用户反馈强，再评估“个人任务 + 粘贴导入”；
- 若只想快速满足 DDL 展示，先用替代方案 E（建为个人日程）。

## 7. 方案细节（建议稿，批准后写入 docs/03）

### 7.1 数据模型

```sql
CREATE TABLE personal_tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL REFERENCES users(id),
    title TEXT NOT NULL,
    description TEXT,
    due_at DATETIME,
    priority TEXT NOT NULL DEFAULT 'normal',   -- low/normal/high
    status TEXT NOT NULL DEFAULT 'todo',       -- todo/doing/done
    completed_at DATETIME,
    source TEXT NOT NULL DEFAULT 'manual',     -- manual/paste/csv
    external_uid TEXT,
    import_batch_id TEXT,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    deleted_at DATETIME
);

CREATE INDEX ix_personal_tasks_user_due
    ON personal_tasks(user_id, due_at);
CREATE UNIQUE INDEX ux_personal_tasks_external
    ON personal_tasks(user_id, source, external_uid)
    WHERE external_uid IS NOT NULL;
```

### 7.2 API 草案

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/me/tasks?status&limit&offset` | 个人任务列表 |
| POST | `/me/tasks` | 新建，201 |
| PATCH | `/me/tasks/{task_id}` | 编辑/完成/重开 |
| DELETE | `/me/tasks/{task_id}` | 软删除，204 |
| POST | `/me/tasks/import?dry_run=true\|false` | 粘贴/CSV 导入预览/提交 |
| DELETE | `/me/tasks/imports/{batch_id}` | 撤销批次，204 |

### 7.3 DDL 导入格式

- 粘贴文本：一行一条，支持“课程 - 作业 - 截止时间”或“截止时间 作业”。
- CSV：列建议 `title,due_at,course,priority`；缺列报错，不静默猜。
- 解析日期/时间复用 CR-004 Quick Add 的规则（若已实现）或独立实现；不重复造两套日期解析。
- 预览显示：标题、截止时间、优先级、重复项、警告；提交前不写库。
- 截止时间无时间时默认 23:59（用户时区）；无年份时按当前年并提示。
- 去重：`(user_id, source, external_uid)`；无外部 id 用 `hash(title+due_at)`。
- 文件限制：≤ 1 MB、≤ 500 条；超限 400。

### 7.4 前端

- “我的任务”页或“我的日程”任务区；与团队任务视觉分区。
- 导入向导：粘贴/上传 → 预览 → 提交 → 撤销。
- 逾期标识；完成/重开；优先级筛选。
- 明确提示“个人任务队友不可见”。
