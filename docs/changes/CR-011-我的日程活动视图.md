# CR-011 · “我的日程”并入我参加的团队活动

- 状态：**用户要求 · 已实施 · 待 A/B 复核**（2026-11-12）
- 提出：用户 2026-11-12（“团队活动里涉及到用户参与的活动应该自动加入到个人日历里吧”）
- 关联：CR-002 / CAL-9 个人日历；CAL-1 团队日历
- 契约影响：**新增 1 个只读端点** `GET /me/team-events`（HTTP 操作 39→40）；无表结构变更

## 1. 背景

CR-002 只把“我的日程”做成个人事件，团队活动仍需回到团队日历查看。用户希望个人日历能直接看到自己参与的团队活动。

## 2. 方案比较

| 方案 | 做法 | 结论 |
|---|---|---|
| A 物化复制 | 邀请/改期时写入 `personal_events` | 拒绝：改期、取消、移除邀请要双向同步，容易产生脏数据与“幽灵事件” |
| B 读通知表投影 | 从 `notifications` 里还原活动 | 拒绝：依赖通知内容与保留策略，信息不全 |
| C 实时投影（本方案） | 读 `events` + `event_participants`，按当前 token 聚合 | **采用**：无需迁移，改期/取消/拒绝自动生效 |

## 3. 规则

- `attending`：我所在团队中，我 **accepted / tentative** 且未取消、未删除、未开始以外范围内的活动。
- `invites`：我在其中 **pending** 的活动（待我回应）。
- `declined` 不出现；被移除邀请（`responded_at` 为空）不出现。
- 只返回活动可见信息；私密活动只有参与者本人能看到，非参与者本来就被过滤。
- 范围参数 `from/to` 必填、带时区、≤92 天（与个人日历一致）。
- 只读：个人日程里点“查看活动”跳到团队活动详情，修改仍在团队日历完成。
- 个人页面把团队活动与个人事件按天合并展示；团队活动标“邀”（待回应，绿）或“会”（已接受，蓝）。
