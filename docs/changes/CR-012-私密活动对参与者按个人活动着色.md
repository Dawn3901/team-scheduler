# CR-012 · 私密活动对参与者/组织者按个人活动着色

- 状态：**用户要求 · 已实施 · 待 A/B 复核**（2026-11-12）
- 提出：用户 2026-11-12（“林创建的私密活动在团队日历显示灰色，会误导用户”）
- 关联：CAL-6 颜色语义（[CR-010](CR-010-calendar-semantic-colors-and-tutorial.md)）
- 契约影响：无 API/DB 变更；纯前端颜色判定

## 1. 问题

CR-010 把私密活动统一显示成灰色。但“私密”只约束**别人**：组织者和参与者能看到完整详情，对当事人来说它就是自己的活动，应该和普通个人活动一样是蓝色“需要参加”。

## 2. 规则

| 情况 | 颜色 |
|---|---|
| 我创建或参与的私密活动（`my_response` 非空） | 蓝：需要我参加 |
| 我看不到详情的私密忙碌块（他人的私密） | 灰：私密（仅忙闲背景） |
| 团队活动、我被邀请 | 蓝 |
| 团队活动、未邀请我或我已拒绝 | 绿 |

- 判定函数：`isPrivateForViewer(event) = visibility === "private" && my_response === null`。
- 服务端不变：非参与者在活动列表/忙闲里仍然只看到忙碌块（`event_id/title=null`），脱敏规则不受影响。

## 3. 灰色斜纹的来源与修复

用户截图显示：自己的私密活动是蓝色可点事件，但**同一时段还叠着一条灰色斜纹**。斜纹不是活动颜色，而是团队忙闲层（`backgroundItems`）把该成员的个人忙碌块又画了一遍：

- 服务端忙闲接口对“我看不到详情的私密块”返回 `event_id/title=null`；
- 前端把所有 `title===null` 的块都画成斜纹，包括我自己已经能看到详情的那条。

修复：忙闲层跳过“当前用户 + 与已展示活动同一时间段”的块（`mineBlocks`）；他人的私密忙碌块仍然显示斜纹。

- `e2e/private-color.spec.ts`：注册建队 → 建私密活动 → 周视图事件块左边框为 `rgb(37,99,235)`（蓝），不是 `rgb(107,114,128)`（灰）；同时断言页面没有 `.timeline-busy-block` 斜纹。
