# CR-012 · 私密活动对参与者按个人活动着色 + 我的日程任务视图

- 状态：**用户要求 · 已实施 · 待 A/B 复核**（2026-11-12）
- 提出：用户 2026-11-12（“林创建的私密活动在团队日历显示灰色，会误导用户”）
- 关联：CAL-6 颜色语义（[CR-010](CR-010-calendar-semantic-colors-and-tutorial.md)）
- 契约影响：颜色部分无 API/DB 变更；任务视图新增 **1 个只读端点** `GET /me/tasks`（HTTP 操作 40→41），无表结构变更

## 1. 问题

CR-010 把私密活动统一显示成灰色。但“私密”只约束**别人**：组织者和参与者能看到完整详情，对当事人来说它就是自己的活动，应该和普通个人活动一样是蓝色“需要参加”。

## 2. 规则

| 情况 | 颜色 |
|---|---|
| 我创建或参与的私密活动（`my_response` 非空） | 蓝：需要我参加 |
| 我看不到详情的私密忙碌块（他人的私密） | 灰：私密（仅忙闲背景） |
| 团队活动、我被邀请 | 蓝 |
| 团队活动、未邀请我或我已拒绝 | 绿 |

- 判定函数：`isPrivateForViewer(event) = visibility === "private" && my_response === null`。
- 服务端不变：非参与者在活动列表/忙闲里仍然只看到忙碌块（`event_id/title=null`），脱敏规则不受影响。

## 3. 灰色斜纹的来源与修复

用户截图显示：自己的私密活动是蓝色可点事件，但**同一时段还叠着一条灰色斜纹**。斜纹不是活动颜色，而是团队忙闲层（`backgroundItems`）把该成员的个人忙碌块又画了一遍：

- 服务端忙闲接口对“我看不到详情的私密块”返回 `event_id/title=null`；
- 前端把所有 `title===null` 的块都画成斜纹，包括我自己已经能看到详情的那条。

修复：忙闲层跳过“当前用户 + 与已展示活动同一时间段”的块（`mineBlocks`）；他人的私密忙碌块仍然显示斜纹。

**2026-11-12 二次修复**：用户仍看到自己的灰色斜纹（「仅我」筛选）。原因与加固：

1. 时间字符串可能带微秒（`.000` / `.123456`）或不带，直接比较会漏判 → 统一用 `normalizeIso` 比较；
2. 用户自己的忙碌来源不止团队活动，还有 **个人日历事件**（如 11/13 13:00 宿舍）→ 忙闲层同时排除当前用户的个人事件时间段；
3. 兜底：筛选条件为「仅我 / 我的活动」时，该成员的所有忙碌块本来就是自己的，直接不画斜纹。
4. 「仅我 / 我的活动」下，把自己的**个人日历事件**也画成可点事件（灰色=私人、带“个人”提示），进入团队日历是为了“看自己的时间”，不是把个人事件公开给团队；「全部成员/指定成员」时个人事件仍只在忙闲层、不下发标题。

## 5. 我的日程增加“指派给我的任务”

用户反馈：团队任务不应再回任务看板才能看到。方案同样采用**实时投影**，不复制数据：

- `GET /me/tasks`：我所在团队中指派给我、未完成、未删除的任务；
- 分 `overdue`（已逾期）与 `upcoming`（30 天内到期）两组，按截止时间升序；
- 完成后自动消失；只读，点“查看任务”跳到团队任务看板。

前端在“我的日程”按截止日合并展示：个人事件、团队活动、指派任务三类混排，日期摘要显示“N 项个人 · N 项团队 · N 项任务”。
