# ADR-003 · 实现现状与冻结基线差异

- 状态：**Proposed（待 A/B 批准）**
- 日期：2026-11-11
- 关联：[docs/00 需求与设计框架 v1.0](../00-需求与设计框架-v1.0.md)、[AGENTS.md](../../AGENTS.md) §2/§3、W4-07
- 记录人：AI 整理；不代替项目组批准

## 背景

`docs/00` 是 2026-10-27 冻结的目标基线。实现过程中，出于“不引入未使用依赖”“沿用现有 Android 壳”“单进程课程项目”等取舍，实际代码与基线出现了偏差。此前只在 `docs/03` 与开发者指南中零散标注，读者容易把基线当成现状。

本 ADR 的目的不是改写冻结决策，而是**把差异集中记录、给后续同步提供依据**。在 A/B 批准前，`docs/00` 仍是目标基线，不能据此声称基线已全部实现。

## 差异

| 领域 | 冻结基线（docs/00） | 当前实现 | 原因 / 影响 |
|---|---|---|---|
| 后端调度 | APScheduler 3.x，进程内 | 标准库 asyncio，每 60 秒扫描 | 不新增运行依赖；单进程语义、去重键不变；[docs/03 §6.3](../03-概要设计说明书.md) 已记录 |
| 前端状态 | TanStack Query + Zustand | TanStack Query + 组件内 `useState` / URL | 当前团队、视图、筛选不需要全局 store；未引入 Zustand |
| 表单/校验 | React Hook Form + Zod | `FormData` + 服务端校验 + `fieldErrorMap` | 活动/任务表单规模小；避免两套校验规则 |
| UI 样式 | Tailwind + Radix/shadcn | 手写 CSS（`styles.css` / `demo-parity.css`） | 已有设计 token 与 demo 视觉；未引入 UI 库 |
| Android 壳 | Capacitor 7 + `@capacitor/local-notifications` | 原生 Kotlin WebView + `TeamSyncAndroid` JS 桥 + AlarmManager | 现有 `apps/mobile/todolist` 已是原生工程；不引入 Capacitor 依赖；本地通知、权限、开机重排由原生实现 |
| 压测脚本 | `scripts/bench.py`（W5） | `scripts/company_demo/`（500 人/近万活动） | 原脚本未建立；大公司模拟覆盖更大规模并输出计时；命令见 [docs/dev/11](../dev/11-大公司模拟测试-2026-11-09.md) |
| 演示种子 | 计划 §11.1 原写 5 个任务 | 实际 2 个任务（待办/逾期） | 计划已按实际改为 2 个；其余状态演示时现场创建 |

## 决策

1. **记录当前实现为事实**：文档、命令、测试以仓库实际代码为准；不再写“已计划但不存在”的命令。
2. **`docs/00` 保持冻结基线**：在 A/B 批准本 ADR 前，不把基线改成现状；`docs/02` AND-1、`docs/00` 技术栈表只加“实现说明”链接。
3. **不为了对齐文档而引入依赖**：不新增 Capacitor、Zustand、RHF、Zod、Tailwind、Radix、APScheduler；若后续需要，另开 CR/ADR。
4. **Android 方案二选一**：继续原生 WebView（当前）或回 Capacitor；不允许两套壳并存。回 Capacitor 需要迁移、依赖审批、真机回归。
5. **文档同步范围**：AGENTS、README、开发者指南、验收命令先改为实际；`docs/00`/`docs/02` 的需求语义不变，只注明实现形态。

## 后果

- 正向：读者按文档能跑通；CI/本地命令与实际脚本一致；Android 限制写清楚。
- 负向：`docs/00` 与技术栈表仍是目标而非现状，需要读者跳转本 ADR；Android 真机/编译仍未验证。
- 待办：A/B 批准或拒绝本 ADR；批准后决定是否把 `docs/00`/`docs/02` 的技术选型正式改为现状（走 CR）。
