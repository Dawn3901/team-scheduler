# CR-013 · 个人日历视图改版（月 / 周 / 任务清单）

- 状态：**用户确认 · 实施中**（2026-11-14）
- 提出：用户 2026-11-14（“基本复刻一个团队日历样式的个人日历”）
- 关联：CR-002（个人日历）、CR-011（团队活动投影）、CR-012（颜色与任务视图）
- 契约影响：新增 1 个只读端点 `GET /me/agenda`（HTTP 操作 41→42）；**无表结构变更**

## 1. 目标

把「我的日程」从按天列表改成**基本复刻团队日历**的个人日历：

- 视图：**月 / 周 / 任务清单**（三选一），**没有单日视图**；
- 日历里只出现：我的个人事件、我参加/待回应/待重新确认的团队活动、指派给我的任务；
- 颜色只表达处理状态：**红=紧急、蓝=活动待回应、绿=正常**（已完成任务浅灰）。

## 2. 颜色规则（用户确认）

| 颜色 | 条件 |
|---|---|
| 红（紧急） | 任务：逾期或 24 小时内截止；个人事件：进行中或 2 小时内开始 |
| 蓝（待回应） | 团队活动 `my_response = pending`（含待重新确认） |
| 绿（正常） | 其余：我参加的活动、未来的个人事件、3 天外的任务 |
| 浅灰（完成） | 已完成任务 |

- 阈值集中在前端常量；**不只靠颜色**传达：任务保留“已逾期 / 24 小时内”文字，待回应活动保留“待回应”标记。

## 3. 数据

- 新增 `GET /me/agenda?from&to`（≤92 天）：返回 `{from,to,events,tasks}`；
- `events` 合并个人事件（`kind=personal`）与我在各团队中 accepted/tentative/pending 的活动（`kind=team_event`）；declined、未邀请、被移除邀请、已取消/已删除不返回；
- `tasks` 与 `/me/tasks` 同口径（指派给我、未完成、逾期或 30 天内）；
- 复用现有 `personal.list_range`、`team_feed.my_team_events`、`my_tasks`，**不改表、不改现有端点**。

## 4. `share_busy` 开关（用户确认移除）

- 个人事件编辑弹窗**不再提供**“在团队忙闲中显示为忙碌”开关，默认 `share_busy=true`；
- 后端字段与数据库列保留，旧数据按原值生效，不做迁移；
- 理由：个人事件本应参与团队忙闲（否则“找空闲”会漏），逐条开关容易造成“以为团队能看到”的误解；隐私模式如需另立用户级设置。

## 5. 视图行为

| 视图 | 实现 |
|---|---|
| 月 | 复用 `react-big-calendar`，事件条 + 任务截止 chips，样式与团队日历一致 |
| 周 | 复用 `CalendarTimeline`（空闲折叠、滚轮缩放、跨天分段），无成员分栏 |
| 任务清单 | 现“我的日程”列表，按天分组，作为独立视图 |

- 默认周视图；视图与日期存 `sessionStorage`（`teamsync.my-calendar.ui`）；
- 点团队活动/任务跳团队详情；点个人事件打开编辑弹窗；日历空白格创建个人事件。

## 6. 验收标准

- [ ] 个人日历只有 **月/周/任务清单**，无单日视图；
- [ ] 月/周视图与团队日历视觉一致；
- [ ] 只显示我的个人事件、我参加/待回应的团队活动、指派给我的任务；
- [ ] 未邀请我或我已拒绝的团队活动不出现；
- [ ] 颜色仅红/蓝/绿（+完成浅灰），且有文字标识；
- [ ] `/me/agenda` 权限、范围（≤92 天）、带时区校验正确；
- [ ] 375px 可用；刷新后保留视图；团队日历行为不变；回归全绿。
