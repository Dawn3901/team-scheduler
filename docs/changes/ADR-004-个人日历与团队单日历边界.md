# ADR-004 · 个人日历与“单团队单日历”的边界

- 日期：2026-11-12
- 状态：**Proposed（用户要求实施 CR-002；待 A/B 复核）**
- 关联：[CR-002 个人日历](CR-002-personal-calendar.md)、[docs/00 D2](../00-需求与设计框架-v1.0.md)

## 背景

`docs/00` 的 D2 冻结决策是“一个团队一个共享日历，不建 `calendars` 表，用 `visibility` 区分团队/私密”。

CR-002 要新增用户级 `personal_events`。如果不解释，容易被理解为“团队多日历”，与 D2 冲突。

## 决策

1. 个人日历是**用户级忙碌层**，数据属于 `users`，不属于任何团队；不建 `calendars` 表，不引入 `calendar_id`。
2. D2 仍然成立：团队内只有一个共享日历，团队活动仍用 `visibility = team | private`。
3. 个人事件默认 `share_busy = true`，团队忙闲只合并“时间段 + busy”，不下发标题/地点/描述；用户可关闭。
4. 个人事件不进入团队活动列表、冲突检测、通知与提醒（v1 不生成个人提醒）。
5. 个人变更只向 owner 发 `personal.changed` WS 消息，不触发团队广播。

## 备选方案

- 替代 A（“我的日程”聚合视图）：不动表，但没有独立生命周期，退队后数据仍消失；用户已明确要完整个人日历。
- 替代 B（用 `visibility=private` 团队活动代替）：数据仍属团队，多团队重复创建；不满足“数据跟人走”。
- 改造 `events` 加 nullable `team_id`：回归面过大，已拒绝。

## 影响

- 新增表 `personal_events`（迁移 `6b4e82bbf137`），现有 9 张表零改动。
- 契约新增 4 个 `/me/*` 端点，共 39 个 HTTP 操作。
- `docs/ai/02` 表清单由“7 张核心表”改为“核心表 + 拓展表 + 个人表”。
