## 1. 背景

学生是 TeamSync 的一部分用户，不是全部用户。课表导入对以下场景有价值：

- 学生团队：导入本学期课表，团队忙闲自动避开上课时间；
- 课程项目组：导入固定课程/实验时间，减少手工录入；
- 个人用户：把教务系统/课程表 App 导出的 `.ics` 一次性导入个人日历。

但并非所有用户需要课表。因此本功能**默认不占全局导航**，只作为“我的日程”里的可选入口；不做插件运行时，不做 LMS 账号对接。

本 CR 依赖 CR-002 的 `personal_events`。如果 CR-002 未实现，本 CR 不启动。

## 2. 变更内容

### 2.1 目标

- 支持 `.ics` 文件导入到个人日历；先预览、再提交、可撤销。
- 导入结果只属于当前用户；团队只看到忙碌块，看不到课程标题/地点。
- 不做自动刷新、不做双向同步、不保存任何 LMS 账号密码。
- 通过配置开关/二级入口控制可见性，不影响不用课表的用户。

### 2.3 明确不做（本期）

- **不做 DDL / 乐学自动同步**：不保存学生密码、不服务端爬取；另立 CR-005。
- **不做双向日历同步**：不做 Google/Outlook/CalDAV，不做自动刷新。
- **不做第三方插件运行时**：不加载用户上传代码；导入是内置可选模块。
- **不做个人任务**：DDL 导入需要“个人任务”模型，另行评估。
- **不做 AI 总结**：独立模块，另立 CR/ADR。
- **不导入团队日历**：导入只写个人日历，不自动生成/修改团队活动。
- **不做多文件合并/增量同步**：v1 只支持单次文件导入 + 整批撤销。

| 层级 | 做法 | 本期 |

## 4. 替代方案

### A. 只支持手工录入，不做导入

- 个人日历手工建课程/事务。
- 优点：0 额外成本，无解析风险。
- 缺点：一学期几十条课程，手工成本高；学生场景吸引力弱。
- 适合：CR-002 先上线，观察需求。

### B. 导入为团队内私密活动（不依赖个人日历）

- 复用现有 `visibility=private` 团队活动。
- 优点：3–5 人日，无需新表。
- 缺点：多团队重复、退队丢失、数据不属于用户；与 CR-002 的个人日历方向冲突。
- 适合：明确只服务单团队用户时的临时方案。

### C. 导入到个人日历（本 CR 推荐）

- 在 CR-002 的 `personal_events` 上增加导入元数据，解析 `.ics`。
- 优点：一次导入跨团队生效；退队不丢；隐私边界清晰。
- 缺点：4–6 人日；依赖解析库；RRULE/时区测试成本。
- 适合：确认学生需求、且 CR-002 已落地后。

### D. 服务端对接乐学、抓取 DDL

- 保存学生账号或模拟登录，抓课程/作业。
- **拒绝**：凭据安全、ToS、页面易变、维护成本不可控；不作为课程项目方向。

### E. 完整插件系统

- 把导入做成第三方插件，动态加载。
- **拒绝**：安全、权限沙箱、版本兼容、测试矩阵成本远高于功能本身；导入是内置可选模块即可。

### F. 同 CR 一并做 DDL 导入

- 把课表和 DDL 一起导入。
- **拒绝（本期）**：DDL 需要个人任务模型，和团队任务可见性冲突；拆到 CR-005 单独评估。

## 7. 方案细节（建议稿，批准后写入 docs/03）

### 7.1 数据迁移

```sql
ALTER TABLE personal_events ADD COLUMN source TEXT NOT NULL DEFAULT 'manual';
ALTER TABLE personal_events ADD COLUMN external_uid TEXT;
ALTER TABLE personal_events ADD COLUMN import_batch_id TEXT;

CREATE UNIQUE INDEX ux_personal_events_external
    ON personal_events(user_id, source, external_uid)
    WHERE external_uid IS NOT NULL;
```

- 旧数据自动 `source='manual'`，不影响 CR-002 手工事件。
- `import_batch_id` 用于整批撤销；不建单独批次表，减少表数量。
- 若 CR-002 尚未实现，可与 `personal_events` 建表同一迁移；若已实现，新增迁移。

### 7.2 API 草案

#### POST `/me/events/import/ics?dry_run=true|false`

- `multipart/form-data`，字段 `file`；仅 `.ics`/`text/calendar`。
- `dry_run=true`：只解析并返回预览，不写库。
- `dry_run=false`：写入并返回 `batch_id`。

预览响应：

```json
{
  "dry_run": true,
  "total": 48,
  "create": 45,
  "duplicate": 2,
  "skipped": 1,
  "warnings": ["1 条事件的 RRULE 暂不支持，已跳过"],
  "items": [
    {
      "title": "数据结构",
      "start_at": "2026-11-04T01:00:00Z",
      "end_at": "2026-11-04T02:40:00Z",
      "all_day": false,
      "location": "教三 201",
      "duplicate": false
    }
  ]
}
```

提交响应：

```json
{ "batch_id": "0b6f...", "created": 45, "duplicate": 2, "skipped": 1 }
```

#### DELETE `/me/events/imports/{batch_id}`

- `204`；只软删除该批次导入的事件，不影响手工事件和其他批次。
- 非本人批次：`404 NOT_FOUND`。

### 7.3 ICS 解析规则

- 支持 `VEVENT` 的 `UID/SUMMARY/DTSTART/DTEND/LOCATION/DESCRIPTION/RRULE/EXDATE/RECURRENCE-ID`。
- 循环事件按导入时选择的日期范围展开（默认未来 120 天，UI 可选学期结束日）；单次导入最多 500 条。
- 有 `UID` 时按 `(user_id, source='ics', UID)` 去重；无 `UID` 时用 `hash(summary+start+end)` 生成稳定 key。
- 每次提交生成 `import_batch_id`；撤销只软删除该批次。
- 不支持的 `RRULE` 部分（如 `BYSETPOS`）返回 warning 并跳过该事件，不静默导入错误时间。
- 全天 `VALUE=DATE` 按用户时区 00:00 → 次日 00:00；`TZID`/带偏移时间转 UTC；浮动时间按用户时区解释。
- 文件限制：≤ 1 MB、必须是 `text/calendar`/`.ics`；超限或格式错误返回 400 `VALIDATION_ERROR`。
- 不抓取远程 URL（避免 SSRF）；不执行文件中的任何内容；标题/地点长度沿用现有文本规则。

### 7.4 前端

- “我的日程”页面增加“导入课表”按钮（受 `ENABLE_COURSE_IMPORT` 控制）。
- 导入向导：选择文件 → 选择日期范围 → 预览（创建/重复/跳过/warnings）→ 提交 → 可撤销。
- 预览阶段不写库；提交前可取消。
- 导入后提示“队友只能看到忙碌，不显示课程标题”。
- 移动端 375px 可用；无全局导航入口。

### 7.5 隐私与安全

- 导入文件仅 owner 解析；不落 LMS 凭据。
- 团队忙闲只看到忙碌块，不返回课程标题/地点/描述。
- 文件大小/类型/数量限制；解析失败返回 400，不产生部分写入（事务）。
- 依赖库版本锁定；不引入动态插件加载。
