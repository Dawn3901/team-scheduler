---

## 1. 演示目标

8 分钟内让评委看到四件事：

1. **这是给团队用的**：不是个人待办，有团队、成员、邀请、RSVP。
2. **核心差异化**：团队忙闲 + 冲突提示 + 私密脱敏。
3. **闭环**：活动从创建到 RSVP 到提醒；任务从指派到完成。
4. **工程取舍**：三端一套功能、服务器权威、权限/时区/脱敏有设计。

---

## 2. 演示前准备（提前 30 分钟）

> 项目组固定 2 人；演示团队使用 3 个账号（`lin`/`chen`/`wang`）只是为了展示多成员 RSVP 与忙闲，不代表项目组人数。

### 2.1 环境

- [ ] 后端已启动，`GET /health` 返回 `ok`。
- [ ] Web 已构建/开发服务可访问；局域网另一台设备可打开。
- [ ] Electron 已安装并登录；系统通知权限已开。
- [ ] Android 真机/模拟器已安装 APK；通知/闹钟权限已开。
- [ ] 投屏/分辨率 1920×1080；浏览器缩放 100%。
- [ ] 关闭微信/QQ/系统更新等无关通知。

### 2.2 数据

```bash
make seed   # 重置为演示数据
```

| 账号 | 角色 | 用途 |
|---|---|---|
| `lin` | Owner | 主讲人操作 |
| `chen` | Admin | 被邀请/RSVP |
| `wang` | Member | 冲突/任务负责人 |

预置：

- 团队“软工大作业”，邀请码在投屏上可见。
- 3 个活动：团队周会、需求评审、私密活动。
- 1 个冲突活动：与周会重叠。
- 3 个任务：待办/进行中/逾期。
- 通知：邀请、任务指派各 1 条。

### 2.3 兜底

- [ ] 录屏 1 份（完整 8 分钟）。
- [ ] 截图：日历、冲突弹窗、RSVP、任务、桌面通知、Android 通知。
- [ ] 数据库备份 1 份；种子脚本可 2 分钟重建。
- [ ] 若现场断网：切录屏，口头说明“服务器权威/离线只读”。

## 3. 8 分钟脚本

### 0:00–0:40 背景

**讲**：

> 小组约时间要在群里反复问，谁去谁不去没有状态，任务截止日又不在日历上。TeamSync 把“谁有空、谁去、什么时候截止”放在一张团队日历上。

**做**：展示 Web 周视图（3 人、几个活动）。

---

### 0:40–1:10 三端形态

**讲**：

> Web 全功能；桌面端常驻托盘、弹系统通知；Android 随身查看、本地提醒。三端是一套 React 功能 + 三个壳，不是三套 UI。

**做**：切到桌面托盘图标；手机亮屏。

---

### 1:10–2:20 建队与加入

**做**：

1. 用 `lin` 登录（或已登录）。
2. 展示团队“软工大作业”和邀请码。
3. 切到 `chen` 的浏览器，输入邀请码加入。
4. 回到 `lin`，成员列表出现 `chen`。

**讲**：

> 邀请码入队；角色分 Owner/Admin/Member；所有团队数据按成员隔离。

**兜底**：账号已预登录；邀请码提前复制。

---

### 2:20–3:40 忙闲与冲突

**做**：

1. 周视图切“全部成员”，指出 `wang` 周三 14:00–16:00 忙碌。
2. 新建活动，时间选周三 14:30–15:30，邀请 `wang`。
3. 提交，弹出冲突提示（王/课程实验）。
4. 选择“仍然创建”或改到 16:30。

**讲**：

> 冲突是警告不是阻止；工具不替用户做决定。私密活动在忙闲里只显示“忙碌”，不泄露标题。

**兜底**：预置冲突活动；若弹窗没出，直接打开预置活动详情讲设计。

---

### 3:40–4:50 邀请与 RSVP

**做**：

1. 打开“团队周会”，邀请 `chen`、`wang`。
2. 切到 `chen`，通知角标 + 活动详情，点“接受”。
3. 切到 `wang`，点“待定”。
4. 回到 `lin`，详情显示“接受/待定”。

**讲**：

> RSVP 四态；组织者能看到汇总；拒绝者不再计入冲突。

---

### 4:50–5:40 实时

**做**：

1. 两个浏览器并排（`lin` / `chen`）。
2. `lin` 修改活动时间/地点。
3. `chen` 不刷新，收到提示/数据更新。

**讲**：

> WebSocket 只通知“变了”，HTTP 重取；断线重连后自动刷新。

**兜底**：刷新页面，说明“即使 WS 失败，HTTP 仍是唯一数据源”。

---

### 5:40–6:30 任务

**做**：

1. `lin` 新建任务“完成概要设计”，指派 `wang`，截止周五 18:00。
2. 切到 `wang`，收到通知；点“完成”。
3. 回到日历，截止行变绿；再建一个逾期任务展示红色。

**讲**：

> 任务单负责人、三态、截止日上日历；逾期每日提醒。

---

### 6:30–7:20 提醒

**做**：

1. 提前准备一个 15 分钟后开始的活动。
2. 桌面端弹出系统通知；点击聚焦到活动。
3. Android 弹出本地通知（或展示已排通知列表/录屏）。

**讲**：

> 事件前 15 分钟、任务前 1 小时；通知落库去重；Android 用本地定时通知，不依赖后台推送。

**兜底**：录屏；说明 Android 后台限制。

---

### 7:20–8:00 设计与取舍

**讲**（四句话）：

1. **多租户**：每个团队查询都校验成员；跨团队 404；私密活动服务端脱敏。
2. **时间**：UTC 存储、团队时区显示；全天/跨天有测试。
3. **实时**：WS 只加速，HTTP 是唯一数据源；单进程 + 内存连接表。
4. **取舍**：不做离线写、不做 Android 后台推送、不做多日历/评论；6 周内把 P0 做扎实。

**收尾**：

> 我们不是做了一个功能更多的待办，而是把团队时间、邀约状态、任务截止放到了一张日历上。

## 4. 评委可能追问

| 问题 | 回答要点 |
|---|---|
| 为什么不做离线？ | 离线写 + 冲突合并至少 1.5 周；课程规模服务器权威更稳；明确写进限制。 |
| 为什么 Android 不做推送？ | 需要前台服务/原生权限，6 周风险高；本地定时通知已覆盖“提醒”演示。 |
| 私密活动怎么保证不泄露？ | 服务端序列化脱敏；非参与者详情 404；忙闲只返回时间段；有测试断言。 |
| 多人同时改同一活动怎么办？ | MVP 以最后一次写入为准；冲突提示覆盖时间冲突；版本号/乐观锁是 P1。 |
| 为什么用 SQLite？ | 单团队 ≤50 人/1 万活动足够；WAL；备份就是拷文件；换 PostgreSQL 有 ORM 隔离。 |
| 三端怎么保证一致？ | 同一套 React 构建；平台差异只在壳；API/WS 契约冻结。 |
| AI 写了多少？怎么保证质量？ | 文档先行 + 需求编号 + 契约冻结 + 测试/评审清单；AI 产出必须跑 `make check` 并人工 review。 |
| 最大的难点？ | 多租户权限 + 私密脱敏 + 时区边界；都做了专项测试。 |
